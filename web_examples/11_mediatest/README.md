# 기계 메커니즘 SD 미디어 테스트

`index.html`은 GIF 두 개와 MP4 두 개를 표시하는 페이지입니다. 외부 폰트나 라이브러리는 사용하지 않습니다. 기존 미디어는 수정하지 않았습니다.

| 파일 | 내용 | 크기 |
| --- | --- | --- |
| `test1.gif` | 회전축과 연결부 | 1.89 MiB |
| `test2.gif` | 변속기 기어와 축 | 3.56 MiB |
| `test3.mp4` | 잠금장치의 부품 구성 | 1.95 MiB |
| `test4.mp4` | 테이블 아래의 링크 구조 | 3.10 MiB |

## SD카드에서 확인

1. FAT32 SD카드의 최상위에 `index.html`과 미디어 네 개를 복사합니다.
2. 보드에 SD카드를 넣고 전원을 켭니다.
3. 브라우저에서 `http://보드IP/index.html`을 엽니다. 도메인에서도 `/index.html`로 접속할 수 있습니다.
4. 파일 위치는 **HTML과 같은 폴더**로 둡니다. 미디어를 SD카드의 `media` 폴더에 넣었다면 **SD /media 폴더**를 선택합니다.
5. GIF를 하나씩 재생하고 반복 움직임을 확인합니다.
6. MP4를 하나씩 재생합니다. **중간으로 이동**이나 영상 재생 막대를 사용해서 탐색을 확인합니다.
7. **전송 확인**으로 MIME과 Range 부분 응답을 확인합니다. **기록 저장**으로 결과를 내려받을 수 있습니다.

현재 펌웨어의 SD 공개 파일 기능이 필요합니다. SD에 `index.html`이 있으면 공개 루트에서도 우선 사용하지만, SoftAP 설정 모드의 `/`는 Wi-Fi 설정 화면입니다. 시험할 때는 `/index.html` 주소를 직접 사용하세요. 로드 확인 숫자는 이 브라우저에서 읽은 파일 수이며, 파일이 SD에 저장됐다는 증거는 아닙니다. 서버가 플래시의 같은 이름 파일을 대신 제공할 수도 있으므로 시험 파일의 실제 저장 위치도 확인하세요.

## PC 미리보기

`index.html`을 직접 열면 같은 폴더의 미디어를 재생할 수 있습니다. `file://`에서 전송 확인은 브라우저 보안 제한으로 실패할 수 있습니다. 전송 확인은 HTTP 서버에서 실행하세요.

```powershell
python -m http.server 8767 --bind 127.0.0.1
```

이 폴더에서 실행한 뒤 `http://127.0.0.1:8767/index.html`에 접속합니다. 단순 PC 서버는 Range 요청에 HTTP 200을 반환할 수 있습니다. 이 경우 페이지는 부분 응답 지원을 확인하지 못했다고 표시합니다. PC 재생 성공은 보드에서의 SD 읽기나 클라우드 중계 성공을 의미하지 않습니다.

페이지는 미디어 하나만 로드합니다. 다른 파일을 재생하거나 중지를 누르면 이전 파일의 소스를 해제합니다. 전송 확인은 16바이트를 요청하며, 서버가 전체 파일을 반환하면 본문을 읽지 않고 취소합니다. 영상 재생은 브라우저의 코덱 지원에도 영향을 받습니다.
