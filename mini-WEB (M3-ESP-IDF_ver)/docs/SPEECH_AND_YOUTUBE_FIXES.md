# 음성 HTTPS 경합과 일본어 검색·유튜브 뮤직 수정

## 음성 입출력의 HTTPS busy

기존 Azure·Google·OpenAI 음성 요청은 HTTPS 사용권을 최대 5초 기다린다.
클라우드 웹 중계는 그 사용권을 유지한 채 `esp_http_client_perform()`으로
최대 20초의 long poll(클라이언트 타임아웃 30초)을 수행했다. 중계가 함수에서
반환하기 전에 음성의 5초 대기가 끝나면 STT와 TTS가 모두 busy로 실패할 수 있다.

`cloud_relay.c`의 요청을 SDK streaming API로 변경했다. 연결/요청 헤더는
3초 제한, 응답 헤더·본문은 250ms 읽기 제한을 사용하며 EAGAIN에서 부분
상태를 유지하고 다시 읽는다. 전체 요청 제한은 30초로 유지한다. 음성 등
전용 사용권 요청을 발견하면 중계 작업 자신이 연결을 취소하고 TLS와 응답
버퍼를 해제한 뒤 사용권을 반환한다. 의도적인 양보에는 재연결 backoff를 넣지
않고, 양보 중 다른 HTTPS abort 요청을 새로 시작하지 않는다.

SDK 5.5.5 소스와 헤더에서 API와 반환값을 확인했다. 다른 작업에서 HTTP
핸들을 강제로 닫거나 살아 있는 foreground 사용권을 해제하는 방식은 쓰지 않는다.
실제로 다른 음성/AI/HTTPS 작업이 사용권을 점유하면 경합은 여전히 가능하다.
이 수정은 중계 long poll 때문에 반복 실패하는 경로를 해결하는 소스 수정이며,
새 펌웨어에서의 음성 성공과 대기 시간은 보드에서 확인해야 한다.

## 일본어 검색과 결과 표시

- PC 중계의 기존 `sanitize()`가 검색어와 제목에서 일본어·한자를 모두 제거했다.
  검색어는 별도 `searchText()`로 처리해 원문을 보존하며 제어 문자와 길이만 제한한다.
- 제목·채널명의 표시 필터에도 일본어·CJK를 추가했다. Python/yt-dlp stdout을
  UTF-8로 고정해 Windows 코드페이지가 UTF-8 JSON을 훼손하지 않게 했다.
- 펌웨어 검색어 버퍼는 128바이트에서 385바이트로 늘렸다. UI의 일본어
  100글자(약 300바이트)가 중간에서 잘리지 않는다. URL 인코딩과 URL 버퍼도
  맞춰 늘리고, 큰 작업 버퍼는 기존 단일 검색 작업이 소유하는 PSRAM에 둔다.
- 너무 길거나 잘못된 UTF-8 검색어는 거부하고 화면에 안내한다. 검색 제목
  표시용 포맷 버퍼도 늘려 UTF-8이 다시 잘리지 않게 했다.

## 유튜브 뮤직

- 재생 요청의 대기·제출·실제 시작을 분리한다. 거절된 요청은 짧게 재시도하다
  제한 시간에 오류를 표시한다. 같은 요청을 중복 제출하지 않으며 빠른 실패도
  화면에서 사라지지 않는다. 플레이어 revision은 세션마다 단조 증가한다.
- 음악 목록에도 썸네일을 받는다. 일반 유튜브는 세트 0/1, 뮤직은 2/3을
  사용해 서로 표시 중인 이미지를 덮어쓰지 않는다. 추가 두 세트는 PSRAM
  576,000바이트, 재생 중 표지 복사본은 PSRAM 28,800바이트다. 초기화 실패 시
  부분 할당을 회수한다.
- 썸네일이 READY 이후 도착해도 별도로 갱신한다. 재생 중 표지는 UI가 복사해
  새 검색 후에도 유지한다. 아직 받지 못한 표지는 재생 모양의 기본 표지를 쓴다.
- 홈 아이콘을 빨간 원, 흰 원형 테두리, 흰 재생 삼각형의 벡터 형태로 변경했다.

## 검증 결과와 적용

- `test_relay_yield.cjs`: 실제 C 요청 함수 본문을 모의 SDK에서 실행해 20초 poll
  도중 음성 요청 발생, 부분 쓰기, 헤더/본문 EAGAIN, 취소·제한·오류와 해제 순서를 검사한다.
- `test_ytmusic.cjs`: 실제 C UI 제어 본문에서 재생 제출·대기·실패 유지와 썸네일
  소유 정책을 확인한다. `test_tube.cjs`는 일본어 100글자의 URL 인코딩도 검사한다.
- PC `test_media.mjs`: 합성 영상과 실제 FFmpeg로 일본어 검색 왕복, 썸네일 캐시,
  32kHz 음성 전용 패킷, 세 화질의 영상·MP4 전송을 확인했다.
- 실행 중인 PC 중계 자식 프로세스를 기존 GUI 감독 아래 재시작했다. 실제
  `YOASOBI アイドル` 검색 결과는 영상·음악 각각 10개, 썸네일 28,800바이트,
  첫 음성 패킷 2,560바이트(32kHz mono)였다. 단일 PC 측정에서 검색은 약
  1.66/1.57초, 첫 음성 데이터는 약 3.33초였다. 실제 결과 10개의 제목/채널명에
  필요한 문자는 현재 보드 글꼴에 포함되어 있었다.
- 네이티브 UI 렌더링, 펌웨어 컴파일·링크·플래시, 실제 보드의 음성·화면 동작은
  실행하지 않았다. PC 측정값을 보드 지연으로 간주하지 않는다.

PC 중계는 적용됐다. 보드는 새 소스를 사용자 빌드·플래시해야 한다.

```powershell
.\m3.ps1 -Action Build
.\m3.ps1 -Action Flash -Port COM8
.\m3.ps1 -Action Monitor -Port COM8
```

COM8은 예시다. 보드에서 부팅 후 중계가 연결된 상태로 TTS/STT를 각각 반복하고,
일본어 검색·결과 제목·곡 썸네일·뮤직 재생/곡 넘김·검색 중 음성 요청을 확인한다.
busy가 계속되면 실제 점유 작업과 해당 시점의 보드 로그를 확인해야 한다.
