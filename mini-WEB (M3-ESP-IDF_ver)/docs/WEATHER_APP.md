# M3 시계와 날씨 앱

홈 시계·날짜·날씨 요약을 터치하면 날씨 앱이 열립니다. 추가 앱 페이지의
`날씨`에서도 열 수 있습니다. 기존 시계는 한국 시간을 계속 표시하며, 날씨의
자료 시각과 3일 예보 날짜는 선택 지역의 현지 시간입니다.

## 사용 방법

1. M3를 인터넷이 되는 Wi-Fi에 연결합니다.
2. 홈 시계나 날씨 요약을 누릅니다.
3. 도시명을 입력하고 `도시 검색`을 누른 뒤 검색 결과를 선택합니다.
   한국어·영문 검색을 지원하며 가상키보드로 입력할 수 있습니다.
   같은 이름은 행정구역·국가·위도·경도로 구분합니다. 검색 결과는 최대 5개입니다.
   결과가 없으면 다른 이름이나 영문명을 사용합니다.
4. 프리셋은 서울·부산·울산·인천·대구·대전·광주·제주입니다.
5. 현재 기온·체감온도·습도·풍속과 3일간 최저/최고 기온·강수 확률을 확인합니다.
   화면은 세로로 스크롤합니다. 새로고침 버튼으로 직접 갱신할 수 있습니다.

처음 선택한 기본 지역은 서울입니다. 위치 자동 추적은 사용하지 않습니다.
선택 지역은 SD 카드 루트의 `weather.json`에 저장합니다. SD가 없거나 저장에
실패하면 현재 세션에서는 사용할 수 있고, 화면에 미저장 상태를 표시합니다.
저장은 10초 간격으로 재시도합니다. 마지막 정상 파일은 `weather.json.bak`으로
보존하며, 시작 시 기본 파일이 손상되었으면 백업을 읽습니다.

```json
{"version":1,"name":"울산","area":"Ulsan, KR","latitude":35.5384,"longitude":129.3114}
```

직접 파일을 준비하면 UTF-8 JSON을 사용하고 위도는 -90~90, 경도는 -180~180으로
지정합니다. 프리셋 좌표는 각 도시의 대표 지점이며, 구체적인 동네는 검색하거나
이 파일에서 좌표를 지정합니다. 재부팅하면 저장된 지역을 다시 읽습니다.

온라인일 때 15분마다 자동 갱신하며 실패하면 1분 뒤 재시도합니다. Wi-Fi 복구 시
갱신을 다시 시도합니다. 수동 검색/새로고침에는 2초 대기 간격이 있으며,
검색 결과 선택은 이 간격의 영향을 받지 않습니다. 요청 중에는 중복 작업을 막습니다.
통신 실패·오프라인에서는 메모리에 남은 자료와 이전 자료 표시를 함께 보여 줍니다.
재부팅 후에는 자료를 새로 받아야 합니다. 예보 값이 없으면 0으로 표시하지 않고
`예보 자료 없음`으로 표시합니다.

## API 선택

- 날씨: [Open-Meteo Forecast API](https://open-meteo.com/en/docs)
- 지역 검색: [Open-Meteo Geocoding API](https://open-meteo.com/en/docs/geocoding-api), GeoNames 기반
- [요금·이용 조건](https://open-meteo.com/en/pricing): 무료 비상업용 API는 키와 가입이
  필요 없습니다. 공식 안내의 무료 한도는 하루 10,000회이며, 상업용에는 별도 구독이 필요합니다.
- 날씨 자료의 CC BY 4.0 및 제공자 표기를 앱 하단에 표시합니다.

키가 필요하지 않아 별도 비밀 설정을 추가하지 않습니다. 기존 SD의 Wi-Fi와 AI 키
파일을 변경하지 않습니다. 검색어와 선택한 좌표는 HTTPS로 Open-Meteo에 전송합니다.
인증서 번들로 서버 인증서를 검사하며 자동 리다이렉트는 허용하지 않습니다.

## 구현과 검증 범위

`m3_weather.c`의 단일 작업이 HTTPS와 SD 읽기/쓰기를 담당합니다. LVGL 작업에서는
큐에 요청하고 상태 복사본만 읽습니다. 작업 스택은 내부 RAM 8 KiB이며, 큐 한 칸과
HTTP 제어 메모리가 추가로 필요합니다. 응답 버퍼는 최대 12 KiB를 PSRAM에 임시
할당하고 작업이 끝나면 해제합니다. JSON 트리/TLS 메모리는 별도로 필요하며, 실제
피크 힙·스택 여유·바이너리 크기는 사용자 빌드와 보드에서 측정해야 합니다.
집중 모드와 재시작 중에는 새 작업을 받지 않습니다.

실행한 검사:

- `node tools/test_weather.cjs`: 실제 C 정책 본문을 호스트 모의 환경에서 실행.
  응답 누락/null/범위, 불완전한 예보, 지역 설정 버전·좌표, 결과 수 제한,
  UTF-8 URL 인코딩, 중복 요청·큐 실패·집중 모드 처리 확인.
- 홈 위젯, 사진 작업, 다국어, 일본어, 터치 앱, 시스템 피드백 호스트 검사 통과.
- `python tools/check_weather_syntax.py`: 기존 `build/compile_commands.json`의 플래그로
  변경한 C 파일만 `-fsyntax-only` 검사. 오브젝트·펌웨어를 만들거나 링크하지 않음.
- 공식 API 실요청: 한국어 `울산`, `Seoul` 지역 검색과 울산 현재 날씨·3일 예보
  HTTP 200 확인. 이는 PC 통신 확인이며 보드의 TLS·Wi-Fi 동작 증거가 아님.
- `test_m3_integration.cjs`는 오디오 정지 모의 환경의
  `ReferenceError: m3_feedback_clear is not defined`로 실패.
  변경 전 HEAD에서도 같은 오류를 재현했으며 이번 날씨 변경으로 발생한 실패가 아님.

펌웨어 전체 빌드·링크·플래시와 PC 시뮬레이터 컴파일/렌더링은 실행하지 않았습니다.
시뮬레이터에는 결정적인 모의 날씨와 검색·키보드·프리셋·오프라인 시나리오를 추가했습니다.
새 화면 PNG를 생성하거나 실제 화면 배치를 확인한 상태는 아닙니다.

사용자가 ESP-IDF 5.5.5 환경에서 빌드할 명령:

```powershell
Set-Location -LiteralPath 'C:/Users/work/Desktop/Mini WebServer/mini-WEB (M3-ESP-IDF_ver)'
$env:IDF_PY_BUILD_JOBS = '2'
idf.py build -j 2
```

실제 보드에서는 시계/날씨 터치, 도시 검색과 결과 선택, 프리셋, 스크롤과 키보드,
Wi-Fi 단절/복구, SD 미장착/저장/재부팅 복원, 라디오 재생 중 갱신을 확인해야 합니다.
