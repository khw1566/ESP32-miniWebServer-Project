# SD에서 실행하는 앱 실험

게임 앱에서 **SD 앱**을 누르면 카드의 `/apps` 폴더에 있는 Lua 파일을 자동으로 표시합니다.
목록은 서비스 작업에서 약 3초마다 갱신합니다. 파일을 누르면 별도 작업에서 코드를 읽어
실행합니다. 앱을 종료하거나 게임 화면에서 다른 화면으로 이동하면 실행을 중단합니다.

이번 실험은 SD의 Lua 소스를 실행합니다. ESP32용 C 바이너리를 동적으로 로드하는
방식은 아닙니다. Lua 실행기와 화면 연결 코드는 펌웨어에 들어가며, 모래 테트리스의
게임 규칙은 SD 파일에만 있습니다. 기존 내장 게임은 유지합니다.

## 테스트 게임 넣기

1. M3 펌웨어를 사용자가 빌드하고 업로드합니다.
2. 저장소의 `sd_apps/apps` 폴더를 SD 카드 최상위에 복사합니다.
   최종 위치는 `SD:/apps/sand_tetris.lua`입니다. 준비된 `sd_apps/sand_tetris_sd.zip`을
   카드 최상위에 풀어도 같습니다. 압축 파일 자체를 카드에 넣으면 탐색하지 않습니다.
3. SD 카드를 장착하고 게임 → SD 앱 → `sand_tetris.lua`를 선택합니다.
4. 왼쪽·오른쪽·회전·낙하 버튼으로 조작합니다. 새 게임은 즉시 초기화합니다.
5. 같은 색 모래가 상하좌우로 이어져 양쪽 벽을 연결하면 연결된 모래가 사라지고
   모래 알갱이 수만큼 점수를 얻습니다. 대각선 접촉만으로는 연결되지 않습니다.
   새 블록을 놓을 공간이 없으면 붉은 막대가 표시됩니다. 새 게임으로 다시 시작합니다.

파일을 교체한 뒤 목록에서 다시 실행하면 새 코드를 읽습니다. 실행 중인 앱에는
이미 읽은 코드가 유지됩니다. 실제 SD 제거를 서비스가 확인하면 앱을 중단합니다.
종료는 비동기이므로 즉시 다시 누를 때 작업이 아직 정리 중이면 잠시 뒤 재시도합니다.

## 수박 만들기

`sd_apps/apps/watermelon.lua`를 `SD:/apps/watermelon.lua`로 복사합니다.
`sd_apps/watermelon_sd.zip`을 SD 카드 최상위에 풀어도 됩니다.
모래 테트리스와 함께 넣으려면 `sd_apps/sd_games.zip`을 사용합니다.
SD 앱 실행 기능이 설치된 기기에서는 게임 파일 추가만으로 실행할 수 있습니다.

- 게임 → SD 앱 → `watermelon.lua`를 선택합니다.
- 왼쪽·오른쪽으로 조준하고 아래 또는 회전 버튼으로 과일을 떨어뜨립니다.
  연속 낙하는 12프레임, 약 0.6초 간격으로 제한합니다.
- 같은 단계의 과일이 닿으면 한 단계 큰 과일이 됩니다. 총 11단계이며 최종 목표는
  줄무늬 수박입니다. 수박을 만든 뒤에도 계속 플레이할 수 있습니다.
- 합체 점수는 새 단계의 제곱 × 10입니다. 오른쪽 위에 다음 과일이 표시됩니다.
  처음 떨어지는 과일은 1~5단계 중 무작위로 선택합니다.
- 갓 떨어뜨린 과일에는 20프레임의 유예가 있습니다. 그 이후 과일이 점선 위로
  계속 40프레임, 약 2초 동안 넘치면 게임이 끝납니다. 붉은 게이지는 넘침 시간입니다.
- 이 경량 실험판은 동시에 40개의 과일을 처리합니다. 40개가 남은 상태에서 다시
  낙하하면 게임을 종료합니다. 새 게임 버튼으로 점수와 과일을 초기화합니다.

실제 SD 소스를 WebAssembly Lua에서 1,600프레임 실행해 모든 합체 단계, 정확한
접촉·비동일 과일 충돌·낙하 간격·벽/바닥·넘침 유예·게임 종료·재시작을 검사했습니다.
최대 40개 과일이 모두 수박인 밀집 상태도 포함하며 검사 중 최대 명령 수는
523,000개였습니다. 기기에서 40ms 안에 처리되는지와 터치 조작은 실기 확인이 필요합니다.
`tools/sd_apps/test_watermelon.cjs --preview`의 출력은 실제 Lua 그리기 결과이며,
네이티브 기기 UI 스크린샷은 아닙니다.

## 앱 파일과 API

- 폴더: `/apps` 한 단계, 최대 16개. 하위 폴더와 압축 파일은 읽지 않습니다.
- 이름: 영문·숫자·`_`·`-`와 소문자 `.lua` 확장자, 전체 최대 47바이트.
  한글 파일명과 공백은 이 실험 버전에서 제외합니다.
- 크기: 비어 있지 않은 일반 파일, 최대 64KiB. NUL 바이트와 Lua 바이너리 코드는 거부합니다.
- 목록은 파일명순입니다. 16개를 초과하면 탐색 과정에서 먼저 발견한 16개만 표시합니다.
- 캔버스: 160×192 RGB565, 화면에서는 1.75배로 표시합니다.
- `rect(x, y, width, height, color)`: 채운 사각형. 화면 경계를 벗어난 부분은 잘립니다.
  좌표는 x=-160..160, y=-192..192, 크기는 너비 0..160, 높이 0..192로 제한합니다.
- `score(integer)`: 화면 점수, 0..999999999로 제한합니다.
- `SEED`: 실행마다 제공하는 난수 시드입니다.
- `update(buttons)`: 50ms 간격으로 호출합니다. 작업 시간을 더하면 실제 간격은 길어질 수 있습니다.
  입력은 한 번 소비되는 비트 값입니다: 왼쪽=1, 오른쪽=2, 회전=4, 낙하=8, 새 게임=16.
  여러 입력은 합쳐질 수 있습니다. 기기 최대 FPS는 화면 갱신 상한이며 게임 논리는 별도입니다.

기본 함수 일부와 `math`, `table`만 제공합니다. 문자열 라이브러리, 파일·네트워크·OS·
패키지·디버그·코루틴 API는 제공하지 않습니다. `load`, `dofile`, `loadfile`,
`pcall`, `xpcall`, 메타테이블 설정 등도 제외합니다. 앱에는 SD 쓰기 API가 없습니다.

Lua 힙은 PSRAM 768KiB 한도이며 소스와 세 개의 화면 버퍼도 PSRAM을 사용합니다.
화면 버퍼는 각각 61,440바이트입니다. UI 버퍼는 종료 때, 작업 버퍼·VM은 작업 종료 때
해제합니다. 실행 작업의 내부 스택 24KiB는 실행 요청 때만 생성합니다.
Lua C 호출 중첩은 60회로 제한합니다. 앱 초기화·각 update는 명령 600,000개 또는
40ms를 넘으면 오류로 종료합니다. 명령 훅은 1,000명령마다 확인하므로 시간 제한은
정확한 실시간 마감이 아닙니다. 소스 파싱 및 개별 C 함수 내부에는 이 훅이 호출되지
않으며, 입력 크기·그리기 범위·힙 한도를 함께 사용합니다. 적대적 코드에 대한 완전한
보안 격리를 보장하는 구조로 취급하지 않습니다.

웹서버 집중 모드에서는 탐색과 실행을 시작하지 않습니다. 목록·프레임 공유는 뮤텍스로
보호하며 Lua 작업은 LVGL 객체를 직접 조작하지 않습니다. SD 관리 잠금은 탐색과 소스
읽기에만 사용합니다. 실행 내내 SD 잠금을 잡지는 않습니다.

## 검사와 남은 실기 확인

호스트 검사:

```powershell
node tools/test_sd_apps.cjs
cd tools/sd_apps
npm ci --ignore-scripts
npm test
```

첫 검사는 실제 C 함수에서 파일명·파일 유형/크기·소스 바이트·할당·실행 제한 정책을
추출해 모의 환경에서 실행합니다. 작업 생명주기와 UI 연결은 소스 계약도 확인합니다.
두 번째 검사는 제공한 게임 소스를 미리 빌드된 WebAssembly Lua에서 실행합니다.
모래 테트리스의 벽 연결·모래 보존·1,200프레임, 수박 만들기의 합체·충돌·
넘침 판정·1,600프레임과 두 게임의 재시작·그리기 범위를 검사합니다.
이 실행기는 펌웨어의 Lua 5.4.9 바이너리와 다른 호스트 패키지이므로 실제 보드 실행을
대신하지 않습니다.

프로젝트 지침에 따라 에이전트는 펌웨어와 PC 시뮬레이터를 컴파일하지 않았습니다.
한국어·영어 UI용 목록/실행/오류/빈 목록 시나리오는 추가했으나 새 네이티브 화면은
생성하지 않았습니다. 사용자 빌드 후 OTA 4MiB 슬롯 적합성, Lua 링크, 화면 잘림,
SD 삽입·제거·파일 교체, 긴 게임 실행, 무한 반복/대용량 할당 오류 복귀, Wi-Fi/웹
동시 응답, 작업 스택 여유·내부 힙·PSRAM을 확인해야 합니다. 40ms 제한의 실제 성능은
ESP32-P4에서 측정해야 합니다.

Lua 소스는 공식 배포본의 SHA256을 확인해 저장했으며 라이선스는
`components/m3_lua/lua.h`에 포함되어 있습니다. 원본 정보와 선택한 컴파일 소스는
해당 컴포넌트의 `UPSTREAM.md`, `CMakeLists.txt`에 기록되어 있습니다.
