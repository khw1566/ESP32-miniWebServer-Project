# M3 배터리 상태 표시와 하드웨어 확인

## 현재 확인한 사실

- 대상: GUITION JC4880P443C_I_W, JC-ESP32P4-M3.
- 제조사 사양서 3쪽은 리튬 배터리 인터페이스를 명시한다. 전원 회로도
  `hardware/1_PWR.png`에는 IP5306(U5), 배터리 CN4, USB5V_IN이 있다.
- IP5306 자체에는 배터리 잔량의 LED 표시 기능이 있다. 배터리 회로가
  없다는 의미가 아니다. 충전·승압 기능과 MCU가 읽을 수 있는 통신 연결은 구분한다.
- Injoinic I2C 레지스터 문서 2쪽은 일반 IP5306과 별도로 주문하는
  `IP5306_I2C`를 구분한다. I2C 주소 0xEA는 8비트 표기이며 ESP-IDF의
  7비트 주소는 0x75다. L1/L2가 SCL/SDA, L3가 IRQ로 쓰인다.
- 제조사 공개 전원 회로도에서 U5의 LED1(2번), LED2(3번), LED3(4번)은
  연결되어 있지 않다. BAT+도 MCU ADC로 연결된 선이 보이지 않는다.
  따라서 공개 회로도 기준으로는 MCU의 잔량·충전·유선 감지 경로가 확인되지 않는다.
  실제 보드의 개정판과 칩 변종은 실물/통신 결과로 추가 확인해야 한다.
- I2C 문서 7쪽의 0x70 bit3는 충전 활성, 0x71 bit3는 충전 완료 상태다.
  배터리 유무·입력 전원·정확한 연속 퍼센트를 모두 제공하는 것으로 확대 해석하지 않는다.
  외부 센서는 아직 사용자가 선택한 하드웨어가 아니므로 드라이버를 추가하지 않았다.

## 구현된 화면

- 상단 44px 바의 오른쪽에 벡터 플러그, 배터리 윤곽/채움, 퍼센트,
  충전 번개 표시를 추가했다. 시간·네트워크·오디오와 영역을 분리했다.
- 유선 감지 확인 시 플러그를 표시한다. 배터리가 없다고 확인되면 배터리와
  잔량을 숨긴다. 실제 충전 상태가 확인된 경우에만 배터리에 번개를 표시한다.
- 배터리만 사용, 유선만 사용, 유선+충전, 유선+충전 종료, 20% 이하 저전력,
  감지 불가를 각각 처리한다. 감지 불가 값은 `--`다.
- 현재 실제 하드웨어 백엔드는 미확정이다. 기본 펌웨어가 가짜 유선 상태나
  100% 잔량을 표시하지 않도록 모든 측정의 known 플래그를 false로 유지한다.
  따라서 현재 보드에서는 `--`가 표시되며 실제 감지 완료로 간주하지 않는다.

## 보드에서 다음으로 확인할 내용

부팅 때 기존 GPIO7/8 I2C 버스에서 0x75 주소만 25ms 제한으로 한 번 확인한다.
충전·전압·승압 설정 레지스터에는 쓰지 않는다. 새로운 작업이나 ISR은 없다.

- `No verified battery telemetry; I2C 0x75: ...`: 해당 버스에서 응답 없음.
  이것만으로 칩 변종, 다른 버스 또는 배터리 유무를 확정하지 않는다.
- `I2C 0x75 responds; confirm board revision/IP5306_I2C ...`: 그 주소에서 ACK가
  확인된 것이며 IP5306의 신원과 모든 측정 기능이 확인된 것은 아니다.

사용자 빌드·플래시 후 로그, 실물 보드 리비전, U5 표기를 확인하고 제조사
회로와 대조한다. 이미 보드에 사용 가능한 감지 경로가 있다면 그 경로를
우선 연결한다. MCU 연결이 없다고 확정된 뒤에만 추가 배선을 결정한다.
전원 연결을 바꾸어 검증할 때는 배터리 유무, USB 연결/해제, 충전/완충,
센서 오류를 각각 확인한다.

## 검증 범위

`node tools/test_power_status.cjs`는 실제 C 표시/상태 정규화 함수 본문을
호스트 모의 객체에서 실행해 경계값과 표시 조건을 검사한다. UI 시뮬레이터
시나리오 84~89도 추가했다. 네이티브 시뮬레이터 렌더링, 펌웨어 컴파일·링크,
실물 배터리 감지는 실행하지 않았다. 프로젝트 규칙에 따라 빌드·플래시는
사용자가 실행한다.
