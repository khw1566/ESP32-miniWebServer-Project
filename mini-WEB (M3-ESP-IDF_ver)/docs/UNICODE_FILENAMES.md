# 파일명과 문자 표시

M3 화면의 기본 글꼴 연결은 제목 → Nanum 한글 → M3 CJK subset → Montserrat입니다.
파일·음악 목록, 재생 제목, 폴더 경로 등 기본 LVGL 글꼴을 쓰는 화면에 적용합니다.
일본어 입력 자판이나 일본어 TTS 엔진을 추가하는 변경은 아닙니다.

## 내장 범위

- 기존 한글 완성형 11,172자 및 호환 자모 94자를 유지합니다.
- 일본어 히라가나·가타카나, 반각 가타카나, 가타카나 확장,
  일본어 문장부호와 전각 문자, 결합 탁점·반탁점 표시를 지원합니다.
- JIS X 0208 한자, KS X 1001 한자 4,888자(호환 한자 포함),
  Unicode 17.0 Unihan `kJoyoKanji` 2,140항목을 포함합니다.
  마지막 목록은 일본 상용한자 2,136자와 대체 형태 4자이며, BMP 밖의 `𠮟`도 포함합니다.
- 라틴 확장, 그리스·키릴 문자, 일반 문장부호, 통화·수학 기호,
  원문자 숫자·문자 및 선 그리기 문자 등 합계 9,341개의 추가 글리프입니다.

모든 Unicode 한자나 모든 고유명사를 포괄하는 폰트는 아닙니다. 정확한 코드포인트는
`third_party/unifont/subset-manifest.json`에 있습니다.
글꼴은 [GNU Unifont JP 17.0.05](https://unifoundry.com/pub/unifont/unifont-17.0.05/font-builds/)의
1bpp 비트맵에서 만들었으며, 원본·해시·저작권·OFL 라이선스를 보존했습니다.
상용한자 기준 데이터는 [Unicode Unihan](https://www.unicode.org/reports/tr38/#kJoyoKanji)입니다.

## 파일명 인코딩과 크기

SD FatFs API를 UTF-8로 바꾸고 OEM 코드페이지 옵션을 해제했습니다.
기존 `sdkconfig`에도 다음 reconfigure에서 자동으로 적용됩니다.
기존 파일 이름이나 파일시스템을 변경·포맷하지 않습니다.
음악 표시 이름과 라디오 제목은 UTF-8 문자 경계에서만 자릅니다.
파일 탐색에서 실제 경로로 사용하는 이름을 임의로 잘라 열지 않습니다.
SD 미디어 전용 업로드/WAV 경로도 유효한 UTF-8 이름·공백·괄호를 허용합니다.
경로 구분자·제어문자·FAT 금지문자와 상위 경로 접근은 계속 거부합니다.

현재 제한은 유지합니다. 음악 전체 경로는 383 UTF-8 bytes,
음악 표시 이름은 191 bytes, 파일 목록 이름은 255 bytes입니다.
SD 미디어 전용 업로드 API는 이름 64 bytes, 파일 8MiB입니다.
일반 SD 파일 관리 API는 별도 경로 검사/8MiB 제한을 사용합니다.
기존 SPIFFS 객체명 제한도 유지하므로 Flash 파일은 관리자에 표시된
이름 byte 제한을 따라야 합니다. 일본어 한 글자는 보통 UTF-8 3 bytes입니다.
기존 FATFS_MAX_LFN=128과 ESP-IDF VFS 이름 버퍼의 제한 때문에 매우 긴
이름은 짧은 별칭으로 열거될 수 있습니다.

## 메모리와 확인

추가 폰트의 비트맵/검색표는 합계 310,600 bytes의 읽기 전용 Flash 데이터입니다.
한글 11,266자의 동일 크기 글리프 설명을 계산식으로 바꿔 약 132KiB의
중복 메타데이터를 없앴습니다. 글꼴 데이터 기준 순증가는 약 171KiB이며
최종 앱 크기는 사용자 빌드의 4MiB OTA 슬롯 검사를 확인해야 합니다.
부팅 때 전체 폰트를 내부 RAM/PSRAM에 복사하지 않습니다.
화면에 필요한 한 글자만 LVGL의 기존 A8 draw buffer로 풉니다.

호스트 검사와 글리프 확인(컴파일 없음):

```powershell
node .\tools\test_unicode_filenames.cjs
python .\tools\preview_filename_fonts.py
```

검사는 실제 생성 테이블·콜백·UTF-8 처리 본문을 호스트 객체로 실행하고,
추가 글리프 전체를 원본 비트맵과 비교합니다. `font_preview.png`는 글리프 확인용이며
PC UI 렌더러나 실기 화면 캡처가 아닙니다. PC 시뮬레이터 소스에는 파일·음악 목록의
한글/일본어/한자/기호 샘플을 넣었습니다. 사용자 컴파일 후 해당 화면을 확인하세요.

사용자 ESP-IDF 터미널에서 기존 프로젝트를 다시 빌드합니다:

```powershell
idf.py reconfigure build
```

실기에서는 `春の音楽（特別版）①.mp3`, `ひらがな・カタカナ.wav`,
`韓國漢字 音樂.aac` 같은 파일의 표시와 재생을 확인하세요.
재생 성공/오류, 인코딩, 글리프 누락을 구분할 수 있도록 원래 이름을 유지합니다.
