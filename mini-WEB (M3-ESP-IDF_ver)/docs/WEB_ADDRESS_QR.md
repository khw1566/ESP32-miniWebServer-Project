# 도메인·IPv6 접속 QR

홈 화면 첫 번째 **웹 서버** 앱에서 **도메인 / IPv6 / IPv4 / .local**을 선택합니다.
네 종류의 탭은 주소가 없을 때도 표시됩니다. 선택한 주소가 없으면 다른 주소로
바꾸지 않고 대기 이유를 표시합니다. QR은 흑백 216px, 흰 여백 32px입니다.
주소가 바뀌면 자동 갱신하며, 같은 주소는 매 화면 갱신마다 다시 생성하지 않습니다.

| 탭 | 주소와 사용 조건 |
| --- | --- |
| 도메인 | 기존 설정 `CONFIG_MINI_WEB_PUBLIC_HOST`, 또는 `https://m3-기기MAC.audreaming.com/`. 릴레이가 오프라인이어도 주소와 QR을 표시하며 연결 상태를 별도로 안내합니다. |
| IPv6 | 현재 Wi-Fi에 발급된 preferred 공인 IPv6 주소. `http://[IPv6주소]/` 형식으로 인코딩합니다. 주소 만료·연결 해제 시 기존 QR을 지웁니다. |
| IPv4 | 같은 네트워크에서 사용하는 보드 IP. 설정 SoftAP에서는 `http://192.168.4.1/setup`. |
| .local | 실제 mDNS 호스트 이름. 같은 Wi-Fi에서 사용하며 mDNS가 준비된 뒤 QR을 표시합니다. |

도메인 화면은 릴레이 미등록, Wi-Fi 미연결, 시간 동기화, TLS 메모리 대기,
AI 처리 중 일시 대기를 구분합니다. 주소 표시는 DNS·서버 등록 완료나 외부 접속
성공을 보장하지 않습니다. 기존 Factory 등록과 릴레이 설정은 유지됩니다.

IPv6는 `2000::/3` 범위의 현재 공인 주소만 사용합니다. `fe80::` 링크 로컬,
`fc00::/7` 사설 주소와 `미발급` 문구는 QR로 만들지 않습니다. **IPv6 주소 재요청**은
기존 네트워크 작업 큐에서 Router Solicitation을 다시 요청합니다. Wi-Fi를 끊거나
netif를 다시 등록하지 않습니다. 공유기에서 공인 대역이 오지 않으면 통신사 IPv6와
공유기 RA / SLAAC 설정을 확인해야 합니다. 접속하는 휴대폰에도 IPv6가 필요하며
외부 접근은 공유기의 IPv6 방화벽 규칙에 따릅니다.

## 검증

`node tools/test_web_qr.cjs`는 실제 C 함수 본문을 호스트 환경에 옮겨 주소 검증,
버퍼 길이, 연결 해제, 주소 변경, QR 캐시·생성 실패·재시도 및 도메인 상태를 검사합니다.
`node tools/test_touch_apps.cjs`는 IPv6 재요청이 Wi-Fi 저장·재연결·SoftAP 전환 없이
처리되는 경로를 검사합니다. 네트워크·LVGL 호출은 모의 값입니다.

PC 시뮬레이터에는 한국어·영어·일본어 공통으로 도메인, IPv6, IPv4, mDNS,
IPv6 미발급 및 도메인 오프라인 화면 시나리오를 추가했습니다. 프로젝트 지침에 따라
이번 수정에서 네이티브 PC/펌웨어 컴파일·업로드는 실행하지 않습니다.

사용자 빌드·업로드 후 홈 첫 아이콘을 열고 QR 네 종류를 휴대폰으로 스캔하세요.
IPv6 미발급→발급, Wi-Fi 연결 해제→재연결, 도메인 미등록→온라인 상태와
한국어·영어·일본어에서 주소·도움말·재요청 버튼 접근성을 확인하세요.
실제 DNS/릴레이/방화벽 접속과 카메라 QR 인식은 보드에서 별도 확인이 필요합니다.
