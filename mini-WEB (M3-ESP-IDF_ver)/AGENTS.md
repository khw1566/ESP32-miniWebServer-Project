# M3 펌웨어 개발 지침

이 지침은 `mini-WEB (M3-ESP-IDF_ver)`와 하위 폴더에 적용한다. 저장소의
`.agents/rules/project_rules.md`를 함께 따른다. M1·S3·C3 등 다른 보드에
M3 메모리 설정이나 핀 설정을 그대로 적용하지 않는다.

## ESP-IDF 개발 스킬

- M3 펌웨어 구현·수정·빌드 오류 분석에는 `espidf-verify`를 사용한다.
  사용자 스킬 폴더의 `espidf-verify/SKILL.md`를 읽고, 미설치 환경에서는
  저장소의 [스킬 원본](../.skill-drafts/espidf-verify/SKILL.md)을 읽는다.
- 변경 전 스킬의 `scripts/preflight.py`에 현재 M3 프로젝트 절대 경로와
  실제 설치된 ESP-IDF 경로를 전달해 타깃·버전·기존 빌드 메타데이터를 확인한다.
  SDK나 관리 컴포넌트가 없으면 누락을 보고하며, API 호환성 확인을 완료했다고 하지 않는다.
- Wi-Fi 변경은 NVS 저장·비밀번호 재사용·부팅 자동 연결·설정 AP 복귀·이벤트와
  재시도의 소유 작업을 함께 확인한다. `test_touch_apps.cjs`와 저장소의
  `tools/test_network_setup.cjs` 중 변경에 해당하는 검사를 실행한다.
- 스킬 참조 문서의 PC 경로·SDK 버전은 과거 환경의 예시다. 현재 설정을 우선한다.
  스킬 설치는 아래 컴파일·플래시 제한을 변경하지 않는다.

## 작업 원칙

- 요청을 코드와 검증 결과로 마무리한다. 기존 기능을 삭제하거나 숨기는 방식으로
  최적화를 대신하지 않는다. 사용자 설정·자격 증명·파티션·OTA 슬롯을 보존한다.
- 수정 전에 현재 파일과 첨부 로그를 읽는다. 다른 작업에서 추가된 기능을
  과거 소스로 덮어쓰지 않는다. 주어진 증거로 확정된 원인과 추정을 구분한다.
- 기본 규칙상 펌웨어 컴파일·플래시는 사용자가 실행한다. `idf.py build/flash`,
  타깃 컴파일러·링커를 에이전트가 실행하지 않는다. PC 시뮬레이터도 기본적으로
  소스 수정과 실행 절차 제공까지 수행하며, 네이티브 컴파일은 사용자가 실행한다.
  사용자가 명시적으로 PC 빌드를 허용한 경우 그 허용은 PC 시뮬레이터에만 적용한다.
- Node/Python 호스트 검사와 컴파일러를 사용하지 않는 CMake fixture는 실행한다.
  화면 수정이 없으면 불필요한 화면 렌더링을 반복하지 않는다.
- 이모지·그림문자를 UI, 코드, 로그, 문서에 추가하지 않는다. 웹 UI는 반응형으로
  유지한다. 실제 API 키는 Git 제외 로컬 헤더에만 보관하고 출력·화면·fixture에 넣지 않는다.

## 최적화 실행

1. 문제가 발생하는 조건을 기록한다. 보드 리비전, 선택 앱·방송국·코덱, 부팅 로그,
   내부 힙·DMA 힙·가장 큰 DMA 블록·PSRAM 잔량을 확인한다.
2. 기존 map/로그는 기존 바이너리의 기준값으로만 쓴다. 현재 소스의 결과로
   간주하지 않는다. 줄이려는 할당의 크기·수명·소유 작업을 먼저 특정한다.
3. 상주 내부 RAM과 피크 내부 RAM을 먼저 줄인다. 대용량 버퍼 확대는 PSRAM에서
   수행하고, 네트워크·디코더·UI·I2S 사이의 소유권과 backpressure를 유지한다.
4. 한 번에 관련 원인만 수정한다. 다른 기능과 안전장치, 취소·오류 경로를 보존한다.
   스택은 추측으로 줄이지 않는다. 실제 high-water mark와 최악 경로가 필요하다.
5. 변경에 맞는 호스트 검사를 실행한다. 실패 시 원인을 수정하고 관련 검사만
   반복한다. 통과한 검사를 이유 없이 계속 넓히거나 반복하지 않는다.
6. 사용자 빌드 후 링크 맵과 같은 시나리오의 보드 로그를 비교한다. 이 단계가
   없으면 절감량은 소스상 계산 또는 기존 map 추정으로 표시한다.

## PSRAM 활용 기준

- 일반 malloc은 PSRAM 우선(`ALWAYSINTERNAL=0`), TLS 힙은 외부 메모리를 사용한다.
  내부 RAM 예약 128KiB는 DMA·내부 전용 할당을 보호하는 정책이며 추가 RAM이 아니다.
- eSpeak BSS는 컴포넌트 `linker.lf`로 PSRAM에 배치한다. 화면 스냅샷·앱 캐시·대화
  버퍼는 `M3_PSRAM_BSS` 또는 명시적인 `MALLOC_CAP_SPIRAM | MALLOC_CAP_8BIT`를 쓴다.
- 라디오 압축/PCM, 음성 녹음, 합성 음성, 영상·썸네일·JSON 등 일반 데이터는
  PSRAM에 둔다. 코덱/I2S가 내부 DMA 버퍼로 복사하는 입력 버퍼까지 내부 RAM에
  고정하지 않는다. 실제 드라이버의 버퍼 요구사항을 확인한다.
- SDIO/I2S DMA 디스크립터와 드라이버가 내부 메모리를 요구하는 버퍼, RTOS TCB,
  spinlock·원자적 제어 상태는 내부 RAM에 유지한다. 드라이버 전체 BSS를 일괄 이동하지 않는다.
- NVS·파일시스템·OTA·TLS/ROM 경로를 호출하는 작업 스택은 내부 RAM에 유지한다.
  외부 스택은 호출 경로와 cache-off 안전성을 입증한 경우에만 별도로 검토한다.
- PSRAM BSS는 0 초기화 데이터에만 적용한다. 초기값이 있는 데이터·인터럽트 상태를
  무작정 속성으로 옮기지 않는다. PSRAM 초기화 실패를 무시하고 계속 부팅하지 않는다.
- 기본 설정 변경은 기존 `sdkconfig`에도 적용되도록 `cmake/memory_policy.cmake`를
  함께 갱신한다. TLS allocator 같은 choice의 반대 옵션도 해제한다.
- 할당 실패는 NULL 사용·무한 재시도·반복 재부팅으로 이어지지 않게 처리한다.
  취소 시 생산 작업 종료를 확인한 뒤 공유 버퍼와 핸들을 해제한다.

## PC 시뮬레이터와 검증

- `tools/ui_sim`은 실제 `main/m3_ui.c`와 LVGL을 사용하는 480×800 화면 렌더러다.
  서비스·마이크·네트워크·메모리 수치는 모의 데이터다. 하드웨어 검증으로 보고하지 않는다.
- UI 변경 시 새 소스로 한국어·영어 화면을 모두 생성하고 PNG를 직접 확인한다.
  실행 파일이 존재한다는 이유만으로 빌드 성공을 판단하지 않는다. 빌드 실패 후
  남은 오래된 EXE나 PNG를 새 결과로 사용하지 않는다.
- 홈 페이지 탐색, 상단 작업 패널/RAM·Flash 그래프, Wi-Fi·고정 IP·가상키보드,
  음성입력 녹음/인식/결과 확인, AI 상태, 라디오 버퍼링/재생/리버퍼링, TTS,
  게임·파일·설정·영상 앱을 해당 변경 범위에 맞춰 확인한다.
- 새 앱/화면을 추가하면 `scenarios.inc`의 앱 수·이름·상태 시나리오를 함께 갱신한다.
  글자 잘림·겹침·스크롤 접근성·키보드 위치·홈 제스처·언어 전환을 확인한다.
- 홈 위젯 변경은 `test_home_widgets.cjs`와 `test_photo_worker.cjs`로 캘린더,
  페이지 선택, 배경/콘텐츠 레이어, 사진 버퍼 소유권·취소·오류 해제를 확인한다.
  실제 사진 디코딩과 스와이프는 PC/실기 결과를 따로 보고한다.
- 기기 설정·집중 모드 변경은 `tools/test_preferences.cjs`와
  `tools/test_device_settings.cjs`로 저장·인증·재시작·복귀·작업 중단 조건을 확인한다.
  실제 밝기·FPS와 집중 모드 자원 절감은 사용자 빌드·실기에서 별도로 확인한다.
- 녹음 앱 변경은 `tools/test_recorder.cjs`와 `tools/test_audio_output.cjs`로
  WAV 헤더·스트리밍·SD 오류·정지 저장·작업 취소·마이크 해제·파일 소유권을 확인한다.
  실제 마이크·SD 쓰기 지연·전원 중단은 호스트 모의 검사와 구분한다.
- 음악은 SD/Flash 목록·재생·일시정지·음량 150·페이지 이동을 확인한다.
  `tools/test_music_player.cjs`로 증폭 포화·재생 취소·오류 후 해제를 검사한다.
- 파일명/글꼴 변경은 `tools/test_unicode_filenames.cjs`와
  `tools/preview_filename_fonts.py`로 실제 테이블·UTF-8 경계·원본 비트맵을 확인한다.
  글리프 PNG는 PC UI 렌더링이나 실기 검증을 대신하지 않는다.
- 큰 글자/일본어/순환 표시 변경은 `test_japanese.cjs`, `test_i18n.cjs`,
  `test_touch_apps.cjs` 및 `preview_large_fonts.py`로 검사한다.
  일본어 번역 변경 후 `generate_japanese.py`로 생성 테이블을 갱신한다.
- 접속 QR 변경은 `test_web_qr.cjs`와 `test_touch_apps.cjs`로 주소 종류별 선택,
  공인 IPv6 URL의 대괄호·길이·만료, 오프라인 도메인 상태, QR 갱신·실패 및
  Wi-Fi 재연결 없는 IPv6 재요청을 검사한다. 실제 QR 스캔·외부 접속은 따로 확인한다.
- 메모리 수정은 `tools/test_dma_memory.cjs`, `tools/test_memory_budget.cjs`,
  `tools/test_psram_policy.cjs`와 관련 라디오·오디오·음성·영상 검사를 실행한다.
- 사용자 빌드 후 `tools/audit_psram.py`로 실제 링크 맵의 eSpeak BSS 배치를 검사한다.
  PC 모의 힙 수치나 source 문자열 검사만으로 내부 RAM 부족 해결을 선언하지 않는다.

## 보드 확인과 완료 보고

실물에서는 Wi-Fi 연결/재연결, SoftAP, 라디오 시작·정지·장시간 재생,
STT 녹음 후 스피커 재개, TTS, 영상·게임 전환을 확인한다. 최소 힙과 가장 큰
DMA 블록, 스택 여유, underrun 및 할당 실패 로그를 비교한다. 단순 부팅 성공은
장시간 안정성의 증거가 아니다. Flash 사용량과 OTA 7.375MiB(0x760000) 슬롯 크기도 사용자 빌드에서 확인한다.

최종 보고는 변경 목적·호스트 검사·PC 렌더링·사용자 빌드·실기 확인을 구분한다.
실행하지 않은 단계와 남은 확인을 명시한다. 상세 절차는
[`docs/OPTIMIZATION_AND_VALIDATION.md`](docs/OPTIMIZATION_AND_VALIDATION.md)를 따른다.

## SD 앱 실행 변경

- `tools/test_sd_apps.cjs`로 실제 C 파일명·파일 유형/크기·소스·할당·실행 제한 정책을 확인한다.
- `tools/sd_apps`에서 `npm ci --ignore-scripts`, `npm test`로 실제 SD 게임 Lua 소스를 검사한다.
  이는 호스트 WebAssembly 실행이며 펌웨어 컴파일이나 실기 확인으로 보고하지 않는다.
- 앱 종료 시 Lua 작업과 UI 버퍼 소유권, SD 잠금 해제, 웹서버 집중 모드 제외를 보존한다.
- 스크립트를 LVGL 작업에서 직접 실행하지 않는다. 새 파일/네트워크 API는 별도 검토한다.
