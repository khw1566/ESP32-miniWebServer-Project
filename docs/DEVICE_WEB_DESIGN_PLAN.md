# 기기별 웹 디자인 스킬 설치·제작 계획

작성일: 2026-10-26 KST. 현재 단계는 계획이며 스킬 설치·웹 교체·기기 배포는 실행하지 않습니다.

## 목표

C3, C3 스페어, S3, S3 Zero, M1, M3에 각기 다른 시각적 성격을 부여합니다.
기기마다 색만 바꾸는 대신 첫 화면 구성, 서체, 정보 밀도, 이미지 사용,
상호작용을 다르게 설계합니다. M1 2번은 이번 기본 대상에서 제외합니다.

외형과 실제 기능은 구분합니다. 현재 펌웨어·저장 공간·연결 가능한 센서나
주변 장치를 확인한 뒤 소개 문구를 확정하며, 모의 데이터는 실제 측정으로
표시하지 않습니다.

## 설치 후보

| 종류 | 후보·출처 | 역할 | 순서 |
| --- | --- | --- | --- |
| 시각 디자인 | Anthropic `frontend-design` | 주제에 맞는 레이아웃·타이포그래피·색상·첫 화면 설계 | 1차 |
| UI 품질 검토 | Vercel `web-design-guidelines` | 접근성·키보드·입력·반응형 등 인터페이스 검토 | 1차 |
| 디자인 변형·완성도 | `pbakaus/impeccable` | craft, critique, polish, bolder, quieter, adapt, optimize 등으로 방향 변형·마감 | Windows/Codex 적용 시험 후 2차 |
| 시각 소재 | 현재 제공되는 `imagegen` | 기기별 대표 이미지·배경 등 필요한 비트맵 제작 | 신규 설치 없이 필요할 때 |
| 레퍼런스 구현 | 공식 카탈로그의 Figma 관련 스킬 | 사용자가 Figma 시안을 줄 때 디자인 규칙 추출·구현 | 선택 |

2026-10-26 공식 curated 목록 조회에서 `frontend-design`은 없었으므로
첫 후보는 제작자의 GitHub 저장소에서 설치할 계획입니다.
같은 이름의 스킬을 중복 설치하지 않고 실제 설치본의 이름·출처·리비전을
기록합니다. Impeccable은 현재 엔진·훅을 포함하므로 배포본 구성과 Codex
호환성을 확인한 뒤 도입 범위를 정합니다.

React 전용 성능 스킬이나 배포 스킬은 이번 디자인 기본 설치에 넣지 않습니다.
현재 보드의 정적 웹 제공 방식에 맞춰 필요한 도구를 선정합니다.

## 기기별 디자인 방향 초안

다음은 제안하는 디자인 방향이며 실제 하드웨어 기능의 확정 목록이 아닙니다.

| 기기 | 시각 방향 | 구별되는 구성 | 소개 주제 초안 |
| --- | --- | --- | --- |
| C3 | 가벼운 미니멀 | 밝은 배경, 간결한 산세리프, 짧은 단일 열, 절제된 이미지 | 작은 보드의 독립 웹서버 |
| C3 스페어 | 산업용 계측기 | 명확한 구획·수치 표시·상태 구분, 기술 도면 같은 구성 | 연결·상태 확인용 시연 |
| S3 | 인터랙티브 기술 전시 | 큰 대표 장면, 단계별 탐색, 사용자가 조작하는 데모 | 처리 여유와 웹 상호작용 |
| S3 Zero | 소형 제품 카탈로그 | 확대된 보드 사진, 치수·핵심 특징, 짧은 제품 설명 | 작은 크기와 설치 활용 |
| M1 | 친근한 터치 안내 | 큰 터치 영역, 명확한 메뉴, 짧은 이용 순서 | 화면 조작과 QR 이용 |
| M3 | 미디어·기능 전시 | 넓은 대표 영역, 사진·오디오 중심 콘텐츠, 기능별 탐색 | 실제 제공되는 미디어·AI 기능 |

각 기기에 `DESIGN.md`를 두고 색상, 서체, 레이아웃, 이미지, 움직임,
피해야 할 표현을 기록합니다. 한 페이지를 만들 때는 주 디자인 스킬 하나를
선택하고, 다른 스킬은 검토·마감 역할로 사용해 서로 방향을 덮어쓰지 않도록 합니다.

## 진행 순서와 산출물

1. **스킬 설치·확인**
   - 후보의 실제 SKILL.md, 의존 도구, 라이선스와 설치 경로를 확인합니다.
   - 1차 스킬을 설치하고 다음 턴에서 인식 여부와 간단한 시안을 확인합니다.
   - Impeccable은 별도 시험 후 추가합니다.
   - 산출물: 설치 목록, 출처·리비전·사용법 기록.
2. **기기별 콘텐츠 명세**
   - 모델·실제 기능·저장 용량·공개 가능한 API·콘텐츠 유형을 조사합니다.
   - 방문자가 첫 화면에서 이해할 특징 3개와 대표 체험 1개를 선정합니다.
   - 산출물: 기기별 소개 문구와 기능 근거 목록.
3. **디자인 비교 시안**
   - 먼저 C3와 M3에서 서로 다른 방향을 시험하고 모바일·데스크톱 시안을 만듭니다.
   - 나머지 기기는 각 방향의 첫 화면을 제작해 한 장의 비교표로 보여줍니다.
   - 산출물: 기기별 DESIGN.md와 전체 비교 미리보기.
4. **정적 웹 구현**
   - 기기별 독립 폴더에 HTML/CSS/JS와 자산을 둡니다.
   - 보드가 제공할 수 있는 정적 파일로 제작하고, 큰 라이브러리·웹폰트·영상은 필요성과 용량을 검토합니다.
   - 실제 API가 없는 센서 조작·AI 요청은 동작하는 기능처럼 표현하지 않습니다.
   - 산출물: 기기별 업로드 패키지, 파일 수·크기 목록.
5. **검토·실물 적용**
   - 모바일·데스크톱, 한국어 줄바꿈, 터치, 키보드 초점, 대비, 로딩·오류 화면을 확인합니다.
   - 로컬 주소와 외부 중계 주소에서 각각 실제 동작을 확인합니다. 외부 중계의 관리자·API 제한을 반영합니다.
   - 기존 파일 백업 후 기기 하나씩 적용합니다. 공개 콘텐츠 업로드와 펌웨어 갱신은 별개로 판단합니다.
   - 산출물: 실제 기기 URL, 화면 캡처, 검증 결과, 복구용 백업.

## 완료 기준

- 기기 이름을 가려도 레이아웃·서체·상호작용에서 서로 다른 방향을 식별할 수 있습니다.
- 각 페이지가 해당 기기의 실제 특징과 대표 사용법을 설명합니다.
- 휴대전화 QR 진입부터 대표 콘텐츠 사용까지 이어집니다.
- 저장 공간과 로컬·공개 중계 제약 안에서 정상 동작합니다.
- 기존 도메인과 QR은 유지하고, 기존 콘텐츠는 복구 가능한 상태로 보관합니다.
