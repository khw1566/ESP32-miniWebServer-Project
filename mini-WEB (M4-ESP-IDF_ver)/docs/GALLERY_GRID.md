# 이미지·동영상 갤러리

갤러리는 파일 탐색기와 별개의 SD 전체 미디어 목록을 사용한다. 숨김 폴더를
제외한 하위 폴더까지 탐색하며 문서·음악·스크립트·임시 다운로드 파일과
폴더 항목은 격자에 표시하지 않는다. 경로는 UTF-8 최대 255바이트다.
파일 수를 고정 개수로 잘라 내지 않고 전체 개수를 센 뒤 한 페이지에 9개씩
3열로 표시한다. 이전·다음 페이지와 새로고침을 제공한다. 정렬은 SD의
디렉터리 탐색 순서이며, 파일을 추가·삭제했으면 새로고침한다.

직접 미리보기를 디코딩하는 이미지는 JPG/JPEG/BMP/PNG다. MJPG/MJPEG 및 MJPEG 코덱 AVI는 첫 JPEG
프레임을 추출한다. MP4는 기존 H.264 Constrained Baseline(최대 640×480),
AAC-LC 제한을 유지하며 첫 디코딩된 영상 프레임을 사용한다. 썸네일 생성은
오디오·재생 시계·영상 재생 작업을 시작하지 않는다. 미리보기에 실패한 파일도
목록에는 남기고 오류 아이콘을 표시한다. GIF/HEIC/WebP/TIFF·MOV/WebM 등 알려진
이미지·동영상 형식도 목록에 포함하지만 디코더가 없는 형식은 오류 표시로 남긴다. 이 경우 기존
`tools/prepare_gallery.py` 변환 도구로 지원 형식으로 바꾼다.

미리보기는 120×120 RGB565다. 큰 이미지를 화면 비율에 맞춘 뒤 가운데
정사각형을 잘라 축소한다. 영상에는 오른쪽 아래 재생 삼각형을 겹친다.
항목을 누르면 432×480 상세보기로 열리며 이미지 원본은 화면에 맞게 표시하고
영상은 재생한다. 뒤로 버튼은 같은 갤러리 페이지로 돌아온다. 상세보기의
이전·다음은 현재 페이지 안에서 순환하며, 파일 탐색기에서 직접 연 항목에는
잘못된 목록으로 이동하지 않도록 이전·다음 버튼을 비활성화한다.

## 작업·메모리 소유권

기존 `m4_gallery` 작업 하나가 목록 탐색과 썸네일을 순차 처리한다. 새 작업을
추가하지 않고 기존 내부 스택을 12 KiB에서 16 KiB로 늘렸다. MP4 미리보기의
디코더 호출 경로를 포함한 실제 스택 여유는 사용자 빌드 후 확인해야 한다.
디렉터리는 경로 길이 범위에 맞춰 최대 128단계까지 반복문으로 탐색한다.
FAT 디렉터리 핸들은 일반 파일 디스크립터 한도를 소비하지 않는다.

- UI 미리보기 9개와 작업의 단일 전달 버퍼는 PSRAM BSS 총 288,000바이트다.
- UI는 전달 버퍼를 자기 캔버스로 복사한다. 작업은 복사 중인 버퍼를 덮어쓰지 않는다.
- 한 페이지의 미리보기만 생성하며 사진 작업 캔버스는 약 405 KiB다. 입력·디코더
  메모리는 기존 파일·해상도·MP4 인덱스 제한을 유지하고 처리 후 해제한다.
- 폴더 변경·상세보기·앱 종료 시 세대 번호로 취소하고 디렉터리·파일·디코더를 닫는다.
- 상세보기 프레임도 세대 번호를 검사해 이전 파일의 준비된 프레임이 다시 나타나지 않는다.
- MP4 인덱스 생성은 썸네일과 재생 사이에서 직렬화한다. 각 인덱스의 할당 풀은
  독립적이며 인덱스 해제가 다른 인덱스 생성의 할당 컨텍스트를 바꾸지 않는다.
- UI 콜백은 파일 탐색·파일 읽기·디코딩을 직접 수행하지 않는다.

## 확인

`node tools/test_gallery_grid.cjs`는 실제 C 본문의 파일 필터링, 재귀 탐색·페이지,
취소·버퍼 소유권, 첫 프레임 처리, RGB565 축소와 3열/상세보기 배치를 모의
객체로 검사한다. `node tools/test_mp4.cjs`는 기존 MP4 재생 경로를 검사한다.
시뮬레이터 시나리오 106~109는 모의 썸네일·페이지·상세보기다.

펌웨어·네이티브 UI 컴파일과 실제 SD·JPEG/H.264 디코더 검증은 실행하지 않았다.
사용자가 빌드·플래시한 뒤 여러 하위 폴더, 9개 초과 미디어, 한글·일본어 파일명,
잘못된 MP4/AVI, SD 오류, 빠른 페이지 전환·종료 및 실제 썸네일/영상 재생을 확인한다.
