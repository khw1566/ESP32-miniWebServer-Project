# M4 부팅 멜로디·효과음·안내음성

설정의 소리 메뉴에서 **부팅 멜로디 / 효과음 / 안내음성**을 각각 켜거나 끄고,
0~100% 음량과 미리 듣기를 조작합니다. 기본 음량은 순서대로 45/35/55%입니다.
기존 미디어 음량은 별도로 유지하며, 전체 무음은 시스템 소리까지 모두 음소거합니다.
변경은 서비스 작업에서 약 2초 간격으로 NVS `m4_device/sound_settings`에 저장됩니다.
기존 화면·미디어 설정의 형식과 NVS 키를 변경하지 않습니다.

소리 메뉴의 **접근성** 버튼을 누르면 안내 방식을 선택하는 메뉴가 열립니다.

- **음성**: 화면 언어에 맞춰 한국어·영어·일본어 안내를 재생합니다.
- **효과음 대체**: 안내음성 대신 구분되는 짧은 음을 재생합니다. 안내음성의
  켜기/끄기와 음량을 그대로 사용하므로 일반 효과음을 꺼도 접근성 안내를 유지합니다.

안내음성을 끄면 일반 동작 알림은 효과음 설정을 따릅니다. 일반 버튼 클릭은 효과음
설정을 따릅니다. 접근성 안내를 포함해 모두 끄려면 안내음성과 효과음을 모두 끕니다.
사용 안 함 또는 음량 0인 항목은 미리 듣기에서도 재생하지 않습니다.

## 제작한 소리

직접 작곡한 6음 부팅 멜로디(약 1.22초)와 클릭·확인·오류·Wi-Fi 설정 효과음 등
5개 WAV를 생성했습니다. 기기는 같은 음을 자체 합성하므로 이 효과음은 SD 없이도
재생됩니다. 모든 음에 짧은 페이드 인·아웃을 적용했습니다.

Google Cloud Text-to-Speech의 여성 음성 `Chirp3-HD-Aoede`로
한국어 `ko-KR`, 영어 `en-US`, 일본어 `ja-JP` 안내 23개씩, 총 69개를 생성했습니다.
준비 완료, Wi-Fi 연결/설정/실패, 저장/오류, 접근성/언어 변경, 앱 15종 이름을 포함합니다.
Google은 이 음성의 나이를 지정하지 않으며, 최종 음색은 샘플을 들어 선택할 수 있습니다.
음성 목록: https://docs.cloud.google.com/text-to-speech/docs/list-voices-and-types

원본 문구와 음성 선택은 `tools/sound_catalog.json`, 실제 출력은
`sd_assets/sounds/m4/{ko,en,ja}/2.wav`~`24.wav`에 있습니다.
PCM16 모노·24 kHz이며 파일당 512 KiB, 10초 이내로 검증합니다.
`manifest.json`은 문구·음성명·요청/오디오 SHA256을 기록하며 API 키는 포함하지 않습니다.

## SD 설치

새 펌웨어를 사용자가 빌드·업로드한 후 SD카드를 PC에 연결하고 저장소 루트에서
아래를 실행합니다. `E:/`는 실제 SD 드라이브로 바꾸세요.

```powershell
python "mini-WEB (M4-ESP-IDF_ver)/tools/install_system_sounds.py" E:/
```

또는 `sd_assets/sounds` 폴더를 SD 루트에 복사합니다. 결과 경로는
`SD:/sounds/m4/ko/2.wav` 등입니다. 배포 ZIP을 SD 루트에 풀어도 됩니다.
설치 도구는 키·Wi-Fi의 `.private` 폴더를 건드리지 않습니다.
SD가 없거나 음성 파일이 없으면 같은 안내 음량의 효과음으로 대체합니다.

문구를 바꾼 뒤 다시 생성할 때:

```powershell
python "mini-WEB (M4-ESP-IDF_ver)/tools/generate_system_sounds.py"
```

Google 키는 Git 제외 `sd_private/.private/api_keys.json`에서만 읽습니다.
기존 문구·음성·정상 WAV가 일치하면 재사용합니다. 새로운 합성 요청은 Google TTS를
사용하며 제공자 과금 정책이 적용됩니다. `--tones-only`는 네트워크를 사용하지 않습니다.

## 재생·검증 범위

기존 오디오 작업 하나가 codec/I2S를 계속 소유합니다. 추가 오디오 작업이나 TLS 호출은
없으며 4개 알림 큐의 데이터는 64바이트입니다. PCM 작업 버퍼는 기존 오디오 작업의
스택을 사용합니다. 설정/접근성 이벤트는 LVGL에서 파일·NVS·오디오 장치를 직접
조작하지 않습니다. 미디어 재생 중 알림은 생략하고 오래된 큐는 폐기합니다.
사용자 재생/녹음 요청은 알림을 취소하며, 웹서버 집중 모드에서는 소리를 실행하지 않습니다.

다음 검사는 호스트 모의 검사 또는 생성 자산 검사이며 펌웨어 컴파일·실기 증거가 아닙니다.

```powershell
node "mini-WEB (M4-ESP-IDF_ver)/tools/test_system_feedback.cjs"
python "mini-WEB (M4-ESP-IDF_ver)/tools/test_system_sound_assets.py"
```

사용자 빌드 후 실제 부팅, 각 항목 미리 듣기/무음/독립 음량, 세 언어의 앱·Wi-Fi 안내,
접근성 효과음 대체, 설정 저장 후 재부팅, SD 없음, 재생 중 사용자 요청 취소를 확인하세요.
PC 시뮬레이터의 `84_system_sounds`~`86_accessibility_tones` 시나리오도 추가했습니다.
프로젝트의 에이전트 직접 컴파일 금지 규칙에 따라 이번 작업에서는 새 PC 화면이나
실기 소리를 검증하지 않았습니다.
