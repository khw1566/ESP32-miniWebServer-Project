# M3 유튜브 중계 서버 (tube.audreaming.com)

M3 보드(ESP32-P4)가 유튜브를 검색하고 재생할 수 있도록 이 PC가 중계합니다. 보드는 `https://tube.audreaming.com`에만 접속하고, 이 주소는 Cloudflare Tunnel로 PC의 `127.0.0.1:8790`에 연결됩니다. 공유기 포트포워딩이나 공인 IP는 필요 없습니다.

```
M3 보드 --HTTPS--> tube.audreaming.com (Cloudflare) --Tunnel--> PC: server.mjs --> yt-dlp / ffmpeg --> YouTube
```

- **검색·채널 목록**: `yt-dlp`로 페이지당 10개를 가져옵니다. 같은 검색어의 다음 페이지는 앞 페이지에 나온 영상을 건너뛰어 중복을 막습니다(10분 캐시).
- **썸네일**: 160x90 RGB565로 변환해 보드가 디코딩 없이 바로 표시합니다. `cache/thumb`에 저장됩니다.
- **재생·화질**: 저화질(256x144 세부 묘사, 8fps, JPEG 품질 18), 표준(384x216, 12fps, 품질 13), 고화질(480x272, 15fps, 품질 9)을 선택합니다. 기본값은 저화질입니다. 하드웨어 JPEG 디코더에 보내는 최종 화면은 모두 480x272이며 음성은 24kHz 모노 PCM입니다. 실제 대역폭은 영상 내용에 따라 달라집니다. 화질을 바꾸면 현재 위치에서 다시 연결합니다.
- **서버 상태**: 앱을 열면 `/api/status`로 토큰 인증, 중계 프로토콜, yt-dlp·ffmpeg 준비 상태를 확인하며 15초 간격으로 갱신합니다. 45초 넘게 갱신하지 못한 상태는 연결됨으로 표시하지 않습니다. 터널 오류와 토큰 거절, PC 서버 업데이트 필요 상태를 구분합니다.
- **SD 저장**: 영상 재생 화면의 `SD카드에 저장`을 누릅니다. PC가 선택 화질의 H.264 Baseline/AAC-LC MP4로 변환한 뒤 보드가 `/sdcard/youtube`에 저장합니다. `저장한 영상`은 해당 폴더를 열며, 파일을 누르면 기존 갤러리에서 음성과 함께 오프라인 재생합니다. PC·Wi-Fi는 저장할 때 필요하고, 완료 후에는 필요하지 않습니다. 파일명에는 제목 일부·영상 ID·화질을 넣습니다.
- **저장 제한**: 라이브와 30분 초과 영상은 제외합니다. 한 번에 한 영상, 파일당 최대 512MiB이며 여유 공간 1MiB를 추가로 확보합니다. 변환 중 또는 전송 중 취소할 수 있습니다. 완료 전에는 `.part`로 보관하고 동기화·닫기·이름 변경이 모두 성공해야 완료 처리합니다. SD 전송 중 다른 SD 작업은 대기하거나 사용 중으로 표시될 수 있습니다. 저장 중 재생과 설정 재시작은 대기합니다. PC MP4 캐시는 최대 12개·약 1GiB로 제한합니다.
- **유튜브 뮤직 앱**: `/api/search?music=1`은 music.youtube.com에서 노래를 찾습니다(`ytmusic.mjs`). 로그인하지 않으면 '노래' 필터가 없으므로 검색 결과의 노래·앨범·싱글과 YouTube Music 공식 재생목록을 순서대로 펼쳐 곡 목록을 만듭니다. 사용자 재생목록은 맨 뒤에 둡니다. 방송 클립, 직캠 같은 일반 영상은 들어가지 않습니다. music.youtube.com 검색이 실패하면 라이브와 20분 넘는 영상을 뺀 일반 유튜브 검색으로 대신합니다. `/api/play?audio=1`은 오디오 트랙 전체를 먼저 `cache/audio`에 받아 둔 뒤(1MiB 범위 요청 4개 병렬) 그 파일에서 32kHz 모노 PCM(약 0.5Mbps)으로 보냅니다. 구간 이동과 다시 듣기는 PC 파일을 읽으므로 빠릅니다. 최근 300곡만 남기고 오래된 곡부터 지웁니다.
- **탐색(seek)**: `?t=초`로 해당 위치부터 다시 변환합니다. googlevideo는 범위 지정 없는 요청을 약 1.5MB에서 끊기 때문에, ffmpeg는 내부 범위 프록시(`127.0.0.1:8791`, 외부 비공개)를 통해 1MB씩 받습니다.
- **보안**: 모든 `/api` 요청에 `x-m3-token` 헤더가 필요합니다. 토큰은 `config.json`과 보드 헤더 `m3_tube_private.h`에만 있으며 둘 다 Git 제외입니다. 재생은 한 번에 하나만 허용합니다.

## 준비물 (이 PC에 이미 설치됨)

- Node.js 20 이상, ffmpeg (PATH), cloudflared (audreaming.com 계정에 로그인됨)
- yt-dlp: `python -m pip install -U "yt-dlp[default]"`. 유튜브 변경으로 검색·재생이 실패하면 먼저 이 명령으로 업데이트하세요. 기존 `yt-dlp.exe`는 삭제된 Python 3.13을 가리켜 동작하지 않으므로, 서버는 `python -m yt_dlp`를 사용합니다(`config.json`의 `ytdlp`로 변경 가능).

## 처음 한 번

```powershell
cd tube-relay
node setup.mjs            # 토큰 생성, config.json 및 보드 헤더 m3_tube_private.h 작성
.\setup-tunnel.ps1        # Cloudflare Tunnel "m3-tube"와 DNS tube.audreaming.com 생성
```

두 단계는 2026-10-13에 이미 수행했습니다. 터널 ID는 `257b5195-6a52-4076-a4b9-5605616da61d`입니다. 그 다음 M3 펌웨어를 빌드·설치합니다. 토큰이 `m3_tube_private.h`로 펌웨어에 들어갑니다.

## 사용할 때마다: `M3TubeRelay.exe`

이 폴더의 **`M3TubeRelay.exe`를 더블클릭**합니다. 창 없이 작업 표시줄 알림 영역(시계 옆)에 빨간 재생 아이콘이 생기고, 중계 서버와 Cloudflare 터널이 백그라운드에서 실행됩니다.

| 아이콘 점 색 | 의미 |
| --- | --- |
| 초록 | 보드에서 사용 가능 (`tube.audreaming.com` 응답 확인) |
| 노랑 | PC 중계 서버는 정상, 터널 연결 대기 중 |
| 빨강 | 중계 서버 시작 대기 중 또는 오류 |

- 아이콘을 오른쪽 클릭하면 다음 메뉴가 나옵니다: 상태, 공개 주소 확인, 중계 서버·터널 로그 보기(`relay.log`, `cloudflared.log`), 폴더 열기, **Windows 시작 시 자동 실행**, 다시 시작, 종료.
- 중계 서버나 터널이 비정상 종료되면 10초 뒤 자동으로 다시 시작하고 알림을 띄웁니다.
- 실행기가 종료되거나 강제 종료되어도 node·cloudflared가 남지 않습니다(Windows Job Object). 두 번 실행하면 이미 실행 중이라고 알려 줍니다.
- 처음 실행할 때 `config.json`이나 `cloudflared.yml`이 없으면 `setup.mjs`, `setup-tunnel.ps1`을 자동으로 실행합니다.
- `M3TubeRelay.exe`는 반드시 이 폴더(`server.mjs` 옆)에 두세요. 바탕화면에는 바로가기만 만드세요.

실행 파일을 다시 만들려면 `.\build-exe.ps1`을 실행합니다. Windows에 포함된 .NET Framework 4 C# 컴파일러를 사용하며, 소스는 `launcher/M3TubeRelay.cs`입니다. 창을 띄워 로그를 직접 보고 싶다면 기존 `.\start.ps1`도 계속 쓸 수 있습니다.

동작 확인은 `https://tube.audreaming.com/healthz`에서 `{"ok":true}`가 나오면 됩니다.

`StartTubeRelay.bat` 또는 `start.ps1`을 두 번 실행하면 기존 실행기를 안내하고 돌아옵니다. `8790` 또는 `8791`의 `EADDRINUSE`는 같은 포트를 쓰는 서버가 이미 있다는 뜻입니다. 실행 중인 창이나 백그라운드 실행기를 종료한 뒤 새 서버를 한 번만 시작하세요. 다른 프로그램이 포트를 사용하면 해당 프로그램을 확인해야 합니다.

검색 실패와 함께 공개 주소가 HTTP 530을 반환하면 터널 연결을 확인하세요.
`cloudflared.log`에 `open C:\Users\khw\Desktop\Mini` 같은 오류가 나오면 공백이 있는 설정 경로가 잘린 것입니다. `start.ps1`은 `--config` 경로를 따옴표로 감싸 전달해야 합니다. 수정된 실행기로 다시 시작하면 되며, 이 수정에는 펌웨어 재설치가 필요하지 않습니다.

토큰을 바꾸려면 `node setup.mjs --rotate`를 실행한 뒤 펌웨어를 다시 빌드합니다.

## 확인 결과와 한계

- 2026-10-15 추가 검증: 실제 사용 Python의 yt-dlp를 2026.08.19로 업데이트했습니다. 새 서버의 내부 `/api/status`와 공개 `/healthz`는 정상 응답했고, 실행기를 두 번 호출해도 포트 8790·8791은 같은 서버 하나만 사용했습니다. 공개 Blender 영상의 저화질 샘플은 PC 내부 경로에서 7.7초 동안 2,100,375바이트·183개 영상 프레임을 받았습니다. 보드 Wi-Fi나 LCD 표시 결과는 아닙니다.
- 합성 3초 영상으로 실제 FFmpeg 변환·HTTP 전송·MP4 형식을 검사했습니다. 저화질/표준/고화질의 전송량은 270,183/397,251/508,817바이트였으며, 실제 YouTube 영상 전체의 대역폭을 뜻하지 않습니다. MP4는 세 화질 모두 H.264 Baseline, 16 정렬 크기, AAC-LC 44.1kHz였습니다. 준비 중 취소 후 부분 파일이 제공되지 않는 것도 검사했습니다.

- 2026-10-15 이 PC의 yt-dlp는 2026.03.17이었고, 이 버전이 준 주소는 앞 1MiB만 받을 수 있고 그 뒤 범위는 403으로 거절되었습니다(최신은 2026.8.19). 이 상태에서는 영상과 음악이 몇 초 뒤 멈춥니다. 서버 로그에 `upstream 403 past the first 1 MiB`가 보이면 위의 yt-dlp 업데이트 명령을 실행하세요. 서버는 시작할 때 yt-dlp 버전을 로그에 남깁니다.

- 호스트 테스트: `node test.mjs`로 문자 정리, JPEG 분리, PCM 분할, 패킷 형식, 섞는 순서와 역압을 검사합니다.
- `npm test`는 MP4 작업의 단일 실행·완료 파일 공개·취소·용량 제한도 검사합니다. FFmpeg와 FFprobe가 있는 환경의 `npm run test:media`는 합성 영상을 세 화질로 실제 변환하고, 내부 HTTP 전송과 MP4의 H.264 Baseline/AAC-LC 형식을 확인합니다. YouTube 계정이나 사용자 토큰은 사용하지 않습니다.
- 실제 측정(2026-10-13, 이 PC): `tube.audreaming.com`을 거친 검색 약 2.3초, 썸네일 약 0.2초, 재생 첫 데이터 약 2.9초가 걸렸습니다. 181초 분량을 받는 동안 프레임 2712개가 모두 정상 JPEG였고, 영상과 음성 패킷의 순서 차이는 최대 107ms였습니다.
- 실제 보드에서의 재생 부드러움, 음성·영상 동기, Wi-Fi(C6) 처리량은 아직 확인하지 않았습니다.
- 보드 화면에 맞게 제목의 이모지와 일본어·중국어 등은 제거하고, 한글·영문·기본 기호만 남깁니다.
- 연령 제한·회원 전용·지역 제한 영상은 재생되지 않을 수 있습니다. 라이브는 시작 위치 이동 없이 재생합니다.
- 유튜브 이용약관은 공식 플레이어 외의 방법으로 영상을 내려받거나 다시 전송하는 것을 제한합니다. 개인 기기에서 개인적으로 볼 때만 사용하고, 외부에 공개하거나 다른 사람에게 서비스하지 마세요.
