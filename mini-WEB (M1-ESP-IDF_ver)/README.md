# Mini WEB M1: ESP32-2432S028R

ESP-IDF 5.5 기준의 첫 온보드 UI 구현입니다. 기존 S3 웹 서버 소스를 복사해 별도 ESP32 프로젝트로 구성했습니다. 기존 S3/C3 프로젝트는 수정하지 않았습니다. 컴파일, 플래시 크기 실측, 실제 LCD/터치/Wi-Fi 동작은 아직 검증하지 않았습니다.

## 구현 범위

- 240 x 320 세로 화면: ILI9341, XPT2046 저항막 터치. SoftAP는 홈에서 수동 시작합니다.
- 주변 Wi-Fi 최대 12개 검색, 목록 선택 또는 SSID 직접 입력.
- 영문 대소문자, 숫자, 공백, ASCII 특수문자 가상 키보드. 넓은 6열 키와 고정된 특문/다음/목록 버튼.
- 비밀번호를 입력한 그대로 표시합니다. WPA2 비밀번호 8~63자 또는 개방형 네트워크. SSID 최대 32바이트 검증.
- 온보드 연결은 성공 후 NVS 저장, 다음 부팅에서 자동 연결. SoftAP 웹 설정은 저장 후 재부팅해 연결을 시도합니다. 실패하면 화면에서 다시 설정합니다.
- 홈의 SoftAP 메뉴, Wi-Fi 가입 QR, 설정 페이지 QR, 4페이지 사용법 제공.
- 같은 공유기에서 접속하는 IPv4 HTTP URL의 QR. 4모듈 흰 여백과 정수 배율 유지.
- 서버 시작/정지, Wi-Fi 재설정, 가동 시간, RSSI, 여유 RAM, SPIFFS 용량, 홈 요청 수 표시.
- 기존 웹 관리자/파일 업로드/미디어 Range 응답/AI 화면 유지. 홈 요청 수는 루트 요청 횟수이며 방문자 수가 아닙니다. 재부팅 시 초기화합니다.
- UI에 필요한 한글 비트맵 서브셋 + LVGL Montserrat ASCII 폰트. UI 문구 변경 시 재생성합니다.

화면은 UI 태스크 하나만 수정합니다. Wi-Fi 스캔·최대 15초 연결 대기·서버 제어는 별도 태스크에서 처리하고 큐로 결과를 전달합니다. 네트워크 작업 중 추가 요청은 막지만 화면 처리는 계속됩니다.

Wi-Fi 검색은 네트워크 매니저에서 STA 모드뿐 아니라 `WIFI_EVENT_STA_START` 수신 여부도 확인합니다. 초기화 후 STA 모드가 이미 설정되어 있어도 드라이버가 시작되지 않았다면 `esp_wifi_start()`를 실행하고 시작 이벤트를 최대 2초 기다린 뒤 검색합니다. 이미 실행 중인 연결은 검색 준비를 위해 중지하지 않습니다. `12290` (`0x3002`, `ESP_ERR_WIFI_NOT_STARTED`) 오류가 발생하던 최초 검색 경로를 수정했습니다. 검색 함수는 AP 개수와 음수 오류 코드를 구분하며 화면·웹 페이지에 오류 이름을 표시합니다. 최초 부팅 검색, 반복 검색, 저장된 Wi-Fi 연결 실패 후 검색, 연결된 상태의 검색을 실물에서 확인해야 합니다.

## 하드웨어 설정

첨부된 `esp32 2432s028 예제/esp32 2432s028 화면복제/firmware`를 기준으로 LCD 설정을 수정했습니다. 일반 ILI9341 초기화 대신 TFT_eSPI의 `ILI9341_2_DRIVER` 전원/프레임/감마 설정을 적용하고, 예제의 `invertDisplay(true)` 보정을 명시적으로 켭니다. 예제는 가로 rotation 1이지만 M1 UI는 세로 240 x 320이므로 같은 라이브러리의 세로 rotation 0에 해당하는 MADCTL 0x48(BGR + MX)을 적용합니다. 좌우 글자 반전 보정은 LCD 방향 설정이며 터치 반전 설정과 별개입니다.

RGB565 바이트 변환은 LVGL 원본 버퍼를 변경하지 않고 별도 DMA 전송 버퍼에 복사하며, 전송 완료 후 다음 프레임을 허용합니다. `LV_COLOR_16_SWAP`이 켜진 기존 설정에서도 중복 스왑하지 않습니다. 두 20라인 버퍼가 합계 19,200바이트를 사용합니다. `main/include/board_display.h`의 색상 반전/미러 설정으로 패널 차이를 조정할 수 있습니다.

재빌드·업로드 후 영문과 한글이 좌우 정상인지, 흰색/검은색이 정상인지, 빨강/초록/파랑이 구분되는지, 스크롤과 키보드 반복 열기에서 잔상·깨짐이 없는지 확인하세요. 원본 예제의 초기화 페이로드와 감마 표 대조 및 RGB565 전송 순서 검사는 통과했지만 실물 출력 정상 여부는 아직 확인하지 않았습니다.

`main/include/board_display.h`에서 핀과 터치 축/반전/최소·최대 원시값을 조정합니다.

| 장치 | 핀 |
| --- | --- |
| LCD | MOSI 13, CLK 14, CS 15, DC 2, BL 21 |
| 터치 | MOSI 32, MISO 39, CLK 25, CS 33, IRQ 36 |
| 향후 SD | MOSI 23, MISO 19, CLK 18, CS 5 |

LCD는 SPI2와 DMA 20라인 버퍼를 사용합니다. 터치는 저속 소프트웨어 SPI로 별도 핀을 사용해 SPI3를 SD 확장용으로 남깁니다. LCD 리셋 핀은 연결하지 않고 ILI9341 소프트웨어 리셋을 사용합니다.

이 설정은 ILI9341이 장착된 R 모델을 가정합니다. ST7789 등 다른 LCD 변형은 드라이버 변경이 필요합니다. 터치 보정값은 초기 추정값이며 실물에서 확인해야 합니다. 참고 핀 자료: https://github.com/marcelrv/Cheap-Yellow-Display-ESP32-2432S028R/blob/main/pinout.txt

## SoftAP로 휴대폰에서 설정하기

### 1. 보드에서 설정용 Wi-Fi 시작

홈에서 **SoftAP**를 누르고 **SoftAP 시작**을 누릅니다. 하단에 **SoftAP 준비 완료**가 표시되면 설정용 Wi-Fi, 포털 DNS, 웹 서버가 준비된 상태입니다. 이미 공유기에 연결되어 있었다면 이 동작으로 공유기 연결을 종료하고 SoftAP로 전환합니다. 이전에 저장한 공유기 SSID와 비밀번호를 지우지는 않습니다. SoftAP는 자동 부팅 옵션이 아니라 이번 실행 중 수동으로 사용하는 설정 모드입니다.

| 항목 | 값 |
| --- | --- |
| 보드 Wi-Fi 이름 | `Mini-WebServer-Setup` |
| 보드 Wi-Fi 비밀번호 | 없음 (개방형 네트워크) |
| 설정 페이지 | `http://192.168.4.1/setup` |
| 동시 접속 수 | 최대 4대 |

### 2. 연결 QR로 보드 Wi-Fi 가입

**연결 QR**을 누른 뒤 휴대폰 카메라로 화면의 QR을 읽고 Wi-Fi 가입을 허용합니다. 이 QR은 웹 주소가 아니라 `Mini-WebServer-Setup`에 가입하는 Wi-Fi 정보입니다. QR 내용은 [ZXing Wi-Fi 형식](https://github.com/zxing/zxing/wiki/Barcode-Contents#wi-fi-network-config-android-ios-11)에 맞춰 `WIFI:T:nopass;S:Mini-WebServer-Setup;;`로 생성합니다.

QR 가입 기능이 지원되지 않으면 휴대폰의 설정 → Wi-Fi에서 `Mini-WebServer-Setup`을 직접 선택합니다. 비밀번호는 입력하지 않습니다. 휴대폰에 **인터넷 연결 없음** 안내가 나오더라도 **연결 유지**를 선택합니다. 이 Wi-Fi는 인터넷 제공용이 아니라 보드 설정용입니다.

### 3. 설정 QR로 웹 페이지 열기

보드 Wi-Fi에 연결된 상태에서 화면의 **설정 QR**을 누릅니다. 다시 카메라로 QR을 읽어 `http://192.168.4.1/setup`을 엽니다. Wi-Fi 가입 QR과 웹 페이지 QR은 서로 다른 동작을 하므로 두 단계가 필요합니다. 설정 페이지가 자동으로 열렸다면 두 번째 QR을 읽지 않고 그 페이지를 사용해도 됩니다.

페이지가 안 열리면 다음 순서로 확인합니다.

1. 휴대폰의 연결된 Wi-Fi 이름이 `Mini-WebServer-Setup`인지 확인합니다.
2. 일반 브라우저의 주소창에 **`http://192.168.4.1/setup`**을 직접 입력합니다. 검색창이나 `https://` 주소를 사용하지 않습니다.
3. 인터넷이 없는 Wi-Fi를 자동으로 해제하는 휴대폰 설정이 있다면 이번 연결을 유지하도록 선택합니다. VPN이 켜져 있다면 일시적으로 끄고 다시 시도합니다.
4. 보드의 **뒤로** → **SoftAP 다시 시작**을 누른 뒤 휴대폰을 다시 연결합니다.

### 4. 실제 공유기 정보를 저장

웹 페이지의 Wi-Fi 목록에서 실제 사용할 **2.4GHz 공유기 SSID**를 선택하고, **공유기의 비밀번호**를 입력해 저장합니다. SoftAP 자체의 비밀번호가 아니라 앞으로 보드가 연결할 공유기의 비밀번호입니다. 숨김 SSID는 직접 입력합니다. 개방형 공유기라면 비밀번호를 비웁니다. SSID는 최대 32바이트, 비밀번호는 비우거나 8~63바이트입니다. 웹 입력은 공백과 특수문자를 URL 디코딩해 저장하며, 길이 초과와 잘못된 인코딩은 거부합니다.

저장 완료 페이지에는 제품의 mDNS 주소와 QR이 나타납니다. 웹 방식은 입력 정보를 NVS에 저장한 후 재부팅해 연결을 시도합니다. 보드의 SoftAP가 사라지고 휴대폰 연결이 끊어지는 것은 재부팅 과정입니다. 저장 완료 메시지는 공유기 연결 성공을 보장하지 않습니다. 실제 연결 상태는 재부팅 후 보드 홈의 Wi-Fi 상태와 IP로 확인합니다.

### 5. 같은 공유기에서 제품 웹 페이지 접속

휴대폰도 보드에 설정한 공유기 Wi-Fi로 연결합니다. 보드의 홈에서 Wi-Fi 상태가 **연결**, IP가 할당된 것을 확인한 후 **접속 QR**을 누릅니다. 휴대폰 카메라로 QR을 읽으면 제품 웹 페이지가 열립니다. 이 QR은 현재 공유기가 할당한 IPv4 주소를 사용합니다.

설정 완료 페이지에서 저장한 `http://m1-v1-2-<MAC 12자리>.local/` 형식의 mDNS 주소도 같은 네트워크에서 사용할 수 있습니다. 휴대폰이 mDNS 이름을 해석하지 못하면 보드의 접속 QR 또는 표시된 IP 주소를 사용합니다. 다음 부팅부터 저장한 공유기에 자동으로 연결하며, SoftAP는 다시 자동으로 열지 않습니다.

### 실패 후 재설정과 종료

- 비밀번호가 틀렸거나 공유기를 찾지 못하면 자동 연결이 실패합니다. 보드 홈에서 **SoftAP → SoftAP 시작**을 다시 실행해 휴대폰으로 정보를 수정하거나 **보드 설정**에서 직접 입력합니다.
- SoftAP 모드를 종료하려면 홈의 **보드 설정**에서 공유기에 연결합니다. DNS 포털을 종료하고 STA 모드로 전환합니다. 저장된 공유기 정보가 있으면 재부팅으로도 일반 연결 모드로 돌아갑니다.
- **서버 제어**는 웹 서버만 시작/정지하며 SoftAP Wi-Fi 자체를 끄는 버튼은 아닙니다. SoftAP에서 서버를 정지하면 설정 QR의 페이지도 열리지 않으므로 다시 시작해야 합니다.
- 홈과 SoftAP 화면의 **사용법**에서 같은 절차를 4페이지로 읽을 수 있습니다. **다음**으로 진행하고 마지막 페이지의 **처음**으로 돌아갑니다. 각 페이지의 홈 버튼은 고정되어 있습니다.
- 여러 보드가 같은 이름으로 SoftAP를 열었다면 이번에 설정할 보드 한 대만 켜고 진행합니다.

## 사용자 빌드 및 업로드

ESP-IDF 5.5 PowerShell 터미널에서 이 폴더로 이동한 후 실행합니다. 최초 빌드 시 컴포넌트 매니저가 고정 버전 LVGL 8.4.0, ILI9341 2.1.0, mDNS 1.13.1을 받으므로 인터넷 연결이 필요합니다.

```powershell
idf.py set-target esp32
idf.py build
idf.py -p COM번호 flash monitor
```

4MB 플래시는 앱 0x2F0000(3008 KiB), SPIFFS 1MB입니다. 기존 코드의 `littlefs` 파티션 이름을 유지하지만 실제 파일시스템은 SPIFFS입니다. 이번 파티션은 factory 단일 앱으로 OTA 슬롯이 없습니다. 웹 OTA는 사용하지 말고 USB로 업데이트합니다. 앱 크기가 3008 KiB를 넘으면 빌드 크기 결과를 기준으로 파티션과 내장 웹 자산을 조정해야 합니다.

한글 폰트 재생성 (컴파일이 아닌 소스 생성):

```powershell
./tools/generate_font.ps1
```

Windows의 Malgun Gothic으로 UI에 사용된 글자만 16 x 20, 1bpp로 래스터화합니다. 생성된 `main/font_m1.c`가 포함되어 있어 일반 빌드에는 폰트 생성 도구가 필요 없습니다. 임의의 한글 SSID 전체나 한글 입력기는 아직 지원하지 않습니다. 키보드로 직접 입력할 수 없는 SSID는 검색 목록에서 선택할 수 있지만 포함되지 않은 글자는 표시되지 않을 수 있습니다. 기업용 802.1X 인증과 64자리 hex PSK도 이번 UI 범위에 포함하지 않습니다.

## 실물 확인 순서

### 온보드 키보드 사용

SSID 또는 비밀번호 입력란을 누르면 키보드가 열립니다. 비밀번호도 마스킹하지 않고 그대로 표시합니다. 상단의 **ABC / abc**는 대소문자 전환, **특문 / 영문**은 특수문자 모드 전환입니다. 각 모드는 **다음** 버튼으로 3페이지를 순환하며 상태 표시줄에 현재 모드와 페이지가 나옵니다. 문자 키는 1행 6개, 한 페이지 최대 12개입니다. 마지막 행의 **SPACE**는 공백, **DEL**은 커서 앞 글자를 삭제합니다.

키보드 상단 오른쪽 **목록**을 누르면 키보드를 닫고 검색 목록과 이전/다음 버튼을 다시 표시합니다. 입력한 SSID와 비밀번호는 유지됩니다. 입력 중 검색·연결·홈 버튼은 표시된 채 비활성화해 실수로 화면을 이동하지 않도록 했습니다. **목록**으로 키보드를 닫은 뒤 **연결**을 누르세요.

문자 입력은 손을 뗐을 때 한 번만 확정하고 길게 누르기 자동 반복을 사용하지 않습니다. 터치는 예제와 같은 Z1/Z2 압력 검사를 적용하고, 처음 두 번의 안정된 좌표를 확인하며 중앙값 필터와 큰 좌표 점프 차단으로 오입력을 줄입니다. 실제 터치 정확도와 체감 입력 속도는 보드에서 확인해야 합니다.

사용자가 확인한 터치 문제는 세로 화면의 좌우 중심선에 대한 좌우 반전입니다. `M1_TOUCH_INVERT_X=1`, `M1_TOUCH_INVERT_Y=0`으로 설정하고 X좌표에 `화면 너비 - 1 - x`를 적용했습니다. LCD 회전과 화면 출력 방향은 변경하지 않았습니다. 업로드 후 왼쪽/오른쪽 버튼과 키보드 양 끝을 눌러 확인합니다.

모든 온보드 화면은 제목/본문/상태 영역을 고정하고 화면 스크롤을 사용하지 않습니다. Wi-Fi 화면은 검색·연결·홈 버튼과 두 입력란을 상단에 유지합니다. 검색 목록은 3개씩 이전/다음으로 넘기며 키보드가 열리면 목록 영역만 대체합니다. 긴 SSID는 표시만 줄이고 선택 시 원문을 사용합니다. 홈과 QR 화면의 하단 버튼도 고정 영역 안에 배치했습니다. 이후 화면에도 같은 규칙을 적용하도록 `AGENTS.md`에 기록했습니다. 터치 좌우 반전은 X축 보정으로 처리하며 Y축 반전은 사용하지 않습니다. LCD 화면 방향과 터치 좌표는 별도로 설정합니다.

1. 최초 부팅에서 화면/색상/터치 위치를 확인합니다. 터치가 반대로 움직이면 축 설정을 조정합니다.
2. Wi-Fi 검색과 숨김 SSID 직접 입력, 개방형/암호 네트워크, 특수문자와 공백 비밀번호를 확인합니다.
3. 틀린 암호로 실패한 뒤 재시도하고, 성공 후 재부팅 자동 연결을 확인합니다.
4. 같은 공유기의 휴대폰에서 QR을 읽고 웹 페이지와 파일 업로드를 확인합니다. 공유기의 클라이언트 격리 기능이 켜져 있으면 접속되지 않을 수 있습니다.
5. 서버 시작/정지, 공유기 연결 끊김, RAM/저장 통계와 루트 요청 카운터를 확인합니다.

저장소 개발 지침에 따라 에이전트는 컴파일/업로드를 실행하지 않았습니다. 기존 AI Studio 모의 테스트는 원본 S3와 M1 모두 동일하게 `read_file/write_file/set_home` 호출 기대에서 실패합니다. 기존 테스트와 현재 AI 로그인/프록시 흐름의 불일치로 보이며 이번 온보드 UI의 검증 결과로 사용할 수 없습니다.

## SD 대용량 미디어 확장

이번 버전에는 SD 마운트와 SD HTTP 경로를 추가하지 않았습니다. 후속 작업은 다음 순서가 적합합니다.

1. SPI3 + SDSPI + FATFS로 `/sdcard`를 마운트하고 카드 부재/오류를 UI에서 표시.
2. 기존 SPIFFS 관리자 자산을 유지하고 `/media/...`를 SD 전용 경로로 등록. 디렉터리 탈출을 차단하고 파일별 접근 정책 적용.
3. 기존 `web_media_range.inc`의 Range 파싱을 재사용하되 SD 경로와 64비트 파일 오프셋에 맞게 분리. 206/416, Content-Length, MIME, HEAD 응답 구현.
4. 파일 전체를 RAM에 읽지 않고 4~16 KiB 버퍼로 전송. 동시 스트림 수를 제한하고 클라이언트 중단 시 파일 핸들을 닫음.
5. 카드 제거와 LCD 갱신이 겹치는 상황, 큰 파일 탐색/재생, Range 시킹, 처리량과 최대 힙 사용량을 실물에서 측정.

ESP32는 파일을 HTTP로 전달하며 동영상 변환은 하지 않습니다. SD 저장공간 확대가 Wi-Fi 전송 속도 확대를 의미하지는 않습니다.
