# M1 RAM 최적화

2026-10-07 소스 변경입니다. PSRAM이 없는 ESP32-2432S028R을 기준으로 합니다.
펌웨어 컴파일, 설치, 실제 RAM 개선량 측정은 아직 수행하지 않았습니다.
현재 보드의 mDNS 주소는 해석되지 않았고 마지막 IP의 상태 API도 시간 초과되어 실물 측정을 할 수 없었습니다.

## 변경한 동작

- 클라우드 중계와 Gemini가 HTTPS 연결을 동시에 유지하지 않습니다. AI 작업이 메모리 사용권을 요청하면 중계 작업이 현재 요청을 마친 뒤 TLS 연결과 4 KiB 응답 버퍼를 해제합니다. AI 성공·오류 처리 후 사용권을 반환하고 중계가 자동으로 다시 연결됩니다.
- 이 시간 동안 로컬 관리자 HTTP 서버는 계속 동작합니다. 외부 도메인은 일시적으로 대기하며, 진행 중인 외부 파일 전송이 중단될 수 있습니다. 관리자 QR 탭은 `paused_ai`를 “AI 처리 중”으로 표시합니다. 연결 정리를 기다리는 상한은 65초이며 중계의 HTTP 제한 시간은 30초입니다.
- AI JSON을 출력할 때 원래 수신 버퍼를 재사용합니다. 별도 출력 문자열과 출력 버퍼 확장·재할당을 없앴습니다. cJSON 트리는 HTTPS 연결 전에 해제합니다. 입력은 48 KiB, 깊이 16, 구조 슬롯 384개로 제한하고 내부 RAM과 최대 연속 공간을 검사합니다. 전체 도구 스키마를 포함한 첫 요청의 예시는 181슬롯입니다.
- AI의 `read_file`은 파일 전체를 복사하지 않고 512바이트씩 읽어 JSON 문자열을 전송합니다. 편집용 버전 해시도 조각 단위로 계산합니다. `list_files`는 파일 하나씩 전송하며 기존 128개 제한을 유지합니다. `write_file`의 버전 확인과 임시 파일·백업·복구 흐름은 유지합니다.
- 홈의 장식용 아이콘과 Wi-Fi·서버 표시를 LVGL 그리기 명령으로 바꿨습니다. 약 75개의 장식 객체 생성을 없애고 카드·버튼 터치 영역은 유지합니다.
- LCD는 RGB565 바이트 순서로 DMA 버퍼에 직접 그립니다. SPI 완료를 기다린 뒤 같은 버퍼를 재사용합니다. 바이트 교환 설정을 끄면 기존 별도 변환 버퍼를 사용하는 대체 경로도 남아 있습니다.
- QR 픽셀 버퍼는 QR 화면에서만 확보하고, 캔버스를 삭제한 뒤 해제합니다.
- 최근 로그 버퍼는 4 KiB에서 2 KiB, SPIFFS 동시 파일 슬롯은 10개에서 6개로 줄였습니다.
- LVGL 반투명 레이어의 목표 버퍼 크기는 24 KiB에서 4 KiB로 줄이고 버튼 확대 효과를 해제했습니다. 레이어가 필요한 객체는 작은 조각으로 그립니다.
- TLS 송신 레코드는 4 KiB에서 2 KiB로 줄였습니다. 서버의 큰 TLS 레코드를 받는 데 필요한 수신 16 KiB와 인증서 검증은 유지합니다.

## 메모리 절감 수치의 범위

| 항목 | 소스에서 확인되는 변화 |
| --- | --- |
| LCD 중복 버퍼 | 240 × 8 × 2 = 3,840바이트 해제 |
| 최근 로그 버퍼 | 상시 2,048바이트 감소 |
| QR 픽셀 버퍼 | QR 화면 밖에서 4,148바이트 확보하지 않음 |
| 반투명 레이어 | 필요한 경우 목표 할당 24,576 → 4,096바이트 |
| TLS 송신 레코드 | 필요한 경우 내용 버퍼 4,096 → 2,048바이트 |
| 홈 아이콘 | 장식 객체와 개별 스타일 할당 제거; 실제 바이트 수는 보드 측정 필요 |
| AI HTTPS | 중계 TLS와 응답 버퍼를 해제한 뒤 시작; TLS 크기는 협상 결과에 따라 달라짐 |
| AI 파일 읽기 | 파일 크기에 따른 전체 파일/JSON 복사를 고정 크기 조각 전송으로 대체 |

이 숫자는 변경한 버퍼 크기이며 실제 전체 힙 증가량을 측정한 값이 아닙니다.
태스크 스택은 실측 없이 축소하지 않았습니다. AI 완료 로그의 `stack_min`은 실제 남았던 최소 스택 바이트 수입니다.

## 확인 결과

다음 Node 검사를 통과했습니다. 메모리 검사에는 플랫폼 독립 C 함수 본문을 제한적으로 변환한 소스 하네스를 사용했으며, ESP32 실행이나 펌웨어 컴파일 검사가 아닙니다.

수정한 C 파일·포함 파일 9개도 SDK 타입을 임시 선언한 문법 파서로 확인했습니다. 실제 SDK 타입 호환성이나 링킹 검사를 대체하지 않습니다.

- `tools/test_memory_budget.cjs`: 사용권 충돌·해제 순서, 시간 초과 복구, 틱 카운터 순환, 모든 JSON 제어 문자와 한글·따옴표·긴 파일 복원, 전체 AI 도구 스키마와 설정 일치.
- `tools/test_dashboard_polling.cjs`: 관리자 스크립트와 중복 조회 방지.
- `tools/test_sd_admin.cjs`: SD 목록·그래프·인증 삭제·오류 처리.
- `tools/test_ai_key.cjs`: 키 저장·재시도·입력 검증.
- `tools/test_ai_studio.cjs`: 파일 읽기·쓰기·홈 지정과 AI 도구 흐름.
- `tools/test_ai_media.cjs`: 이미지·영상 표본과 진단 도구 흐름.

## 새 펌웨어를 설치한 뒤 확인

1. LCD 색상·아이콘·키보드·터치와 QR 표시 후 홈 복귀를 확인합니다.
2. `/api/system`의 `free_heap`, `min_heap`, `internal_free_heap`, `largest_free_block`을 확인합니다. 총 여유 RAM이 있어도 최대 연속 공간이 작으면 TLS가 대기할 수 있습니다.
3. 로컬 관리자, 외부 사이트, SD 파일 업로드를 사용한 뒤 같은 수치를 확인합니다. 업로드와 다운로드를 반복했을 때 여유 RAM이 계속 줄지 않는지 확인합니다.
4. Gemini 요청 중 `cloud_status`가 `paused_ai`, 완료 후 `online`으로 돌아오는지 확인합니다. 실패한 AI 요청 뒤에도 외부 사이트 접속을 확인합니다.
5. AI의 24 KiB에 가까운 파일 읽기와 수정, 따옴표·역슬래시·한글 파일 내용 복원을 확인합니다. 메모리가 부족하면 크기를 줄이라는 응답을 보내며 무리하게 할당하지 않습니다.

기존 개발 지침의 “에이전트 직접 빌드 금지”에 따라 빌드·설치는 사용자가 수행합니다.
메모리 구성은 [Espressif RAM 사용 최소화 가이드](https://docs.espressif.com/projects/esp-idf/en/v5.5.2/esp32/api-guides/performance/ram-usage.html)와 설치된 ESP-IDF 5.5.5·LVGL 8.4.0 소스의 버퍼 및 레이어 구현을 확인했습니다.

## 2차 변경 (2026-10-07)
- Wi-Fi 정적 수신 버퍼 6 → 4개(상시 약 3.2 KiB 감소), 동적 수신 상한 16 → 10개, 동적 송신 상한 16 → 12개, AMPDU 창 6 → 4로 줄였습니다. 부하 시 Wi-Fi 버퍼가 AI용 TLS 메모리를 잠식하는 최대치를 낮추는 목적입니다.
- mbedTLS `DYNAMIC_FREE_CONFIG_DATA`, `DYNAMIC_FREE_CA_CERT`를 켜고 `SSL_KEEP_PEER_CERTIFICATE`를 껐습니다. 상시 유지되는 중계 TLS 세션에서 핸드셰이크 이후 설정 데이터와 서버 인증서 체인 사본을 보관하지 않습니다. 전역 CA 저장소는 사용하지 않으므로 영향이 없습니다.
- `m1_network` 스택 8192 → 6144, `m1_ui` 스택 8192 → 7168로 줄였습니다(3 KiB 감소).
- `memory_monitor.c`를 추가해 60초마다 `MEM` 태그로 내부 힙(free/min/largest)과 태스크별 최소 여유 스택을 기록합니다. 추가 태스크 없이 esp_timer 태스크에서 실행됩니다.
- 기존 `sdkconfig`와 `sdkconfig.defaults`를 함께 수정했습니다. 빌드 전 `idf.py reconfigure`를 권장합니다.
- 다음 단계: `MEM stack_free` 로그에서 `cloud_relay`, `httpd`, `ai_https` 여유가 3 KiB 이상 남으면 해당 스택(10240, 8192, 16384)을 실측값 기준으로 추가 축소할 수 있습니다.

## 3차 변경 (2026-10-07)
- 화면 끄기(화면보호기): 홈 제목줄 오른쪽의 모니터 아이콘을 누르면 LVGL 위젯을 모두 삭제하고 LCD 출력·백라이트를 끈 뒤 DMA 그리기 버퍼를 해제합니다. 보드와 웹서버는 계속 동작합니다. 터치(압력 확인, 3회 연속 감지)로 깨어나며 진입 직후 0.8초는 터치를 무시합니다. 진입 시 `SCREEN_SAVER Enter: free A -> B` 로그로 확보량을 확인합니다.
- FATFS 섹터 크기 4096 → 512. FATFS는 SD카드(512바이트 섹터)에만 쓰이므로 4096 창은 낭비였습니다. 마운트된 볼륨당 3,584바이트, 열린 파일(FATFS_PER_FILE_CACHE)당 3,584바이트가 줄어듭니다. `max_files=6`이므로 SD 파일을 동시에 많이 열 때 최대 약 21 KiB의 최대치가 낮아집니다. SD 순차 쓰기 속도는 다소 낮아질 수 있습니다.
- 스토리지 목록 항목의 이름 버퍼 256 → 129바이트(FATFS 긴 이름 상한 128). 항목 3개 기준 381바이트씩 정적 캐시, 결과 큐 슬롯, `m1_network`·`m1_ui` 스택 사용량에서 각각 줄어듭니다.
- 스토리지 화면의 전체 용량 줄과 페이지 줄을 제거했습니다(라벨 객체 2개 감소).

`sdkconfig`의 FATFS 섹터 설정이 바뀌었으므로 `idf.py fullclean` 후 빌드를 권장합니다.
SD에서 파일 열기·업로드·삭제와 스토리지 화면의 폴더 이동을 다시 확인해야 합니다.
